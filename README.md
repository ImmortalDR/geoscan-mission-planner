# Geoscan Mission Planner

Единый исходный репозиторий работающего MVP: H1 строит покрытие, H2 назначает
БВС и планирует траектории, H3 проверяет результат и показывает его в кабинете.
Демонстрационный набор входов и проверенных выходов находится в [`data/`](data/).

| Компонент | Каталог | Назначение |
| --- | --- | --- |
| H1 | [`h1/h1_coverage/`](h1/h1_coverage/) | Канонический генератор покрытия |
| H2 | [`h2/`](h2/) | Планировщик нескольких БВС и 4D-разведение |
| H3 | [`src/gmp/`](src/gmp/) | API, независимая проверка, очередь и экспорт |
| Web | [`web/h3/`](web/h3/) | Кабинет и карта |
| Данные | [`data/`](data/) | 12 сцен, 14 пар вход/выход, DSM и атрибуция |

H1/H2 включены **как исходники, не как Git submodule**. Для клонирования и
запуска не нужны другие репозитории или каталоги `/root/h1`, `/root/h2`.
Происхождение модулей и границы доказательств: [docs/source-provenance.md](docs/source-provenance.md),
[docs/safety.md](docs/safety.md).

**Экспертам:** [обзор решения](docs/reviewer-guide.md),
[архитектура](docs/architecture.md), [библиотеки](docs/stack.md),
[безопасность и роли](docs/security.md), [все 11 требований](docs/requirements-matrix.md).
В работающем приложении материалы и отчёты доступны на `/documentation` после входа.
Алгоритмы команды используют опубликованные методы и сторонние библиотеки;
авторство реализации не означает изобретение OR-Tools Routing или других базовых методов.

## Быстрый запуск

Проверяемая среда: Linux x86-64 (или WSL2), Python 3.12 и Git.
Интернет нужен для первой установки Python-зависимостей. Node.js и отдельная
сборка интерфейса не требуются. H1 и H2 уже включены; submodules не нужны.

Клонируйте этот репозиторий кнопкой **Code → HTTPS** на GitHub, перейдите
в каталог клона и выполните:

```bash
python3.12 scripts/install.py
bash scripts/run_local.sh
```

Откройте **http://127.0.0.1:8090/**. Скрипт напечатает случайный код входа
в терминале. Выберите сценарий S00, создайте рабочую копию и запустите расчёт;
результат, сертификат и экспорт доступны в интерфейсе. OpenAPI: `/docs`.
Остановка — `Ctrl+C`; повторный запуск — `bash scripts/run_local.sh`.
Для постоянного собственного кода задайте `GMP_ACCESS_CODE` перед запуском.

Состояние сохраняется в `artifacts/h3_workspace/` (SQLite и файлы); каталог
исключён из Git. Можно переопределить `GMP_DATA_DIR`. Режим предназначен для
локального компьютера: сервер слушает только `127.0.0.1`. Docker, PostgreSQL
и секреты рабочего сервера для этого запуска не нужны. Подложка карты может
требовать интернет; `GMP_OFFLINE=1 bash scripts/run_local.sh` отключает внешние
карты и скачивание отсутствующего DSM, сохраняя включённые тестовые сцены.

Если установка завершилась с ошибкой, путь к журналу будет напечатан
установщиком. Проверьте Python 3.12 и доступ к индексу Python-пакетов.

## Проверки

```bash
export PYTHONPATH="$PWD/src:$PWD/h1/h1_coverage/src:$PWD/h2/src:$PWD/h2"
.venv/bin/python data/run_dataset.py verify --integrity
.venv/bin/python scripts/validate_h1_h2_contract.py
.venv/bin/python scripts/run_regression.py
.venv/bin/python scripts/evaluate_algorithms.py
.venv/bin/python scripts/benchmark_algorithms.py
```

Проверка набора не требует сервера или сетевого доступа. Эталонный маршрут не
объявляется глобально оптимальным: иной корректный ответ может быть лучше.
Для PostgreSQL-тестов задайте `GMP_TEST_DATABASE_URL` на одноразовую БД с
именем, оканчивающимся на `_test`: тесты очищают её таблицы. Без переменной
эти проверки явно пропускаются. CI поднимает отдельный PostgreSQL.
Измеренные результаты: [`docs/evidence/`](docs/evidence/). Нагрузочный стенд
и границы измерений описаны в [карте требований](docs/requirements-matrix.md).

## Поставка на 443

Сборщик создаёт отдельный неизменяемый Docker-контекст с манифестом SHA-256:

```bash
python3 deploy/prepare_h3_bundle.py build/geoscan-mvp
python3 deploy/bootstrap.py /secure/geoscan-demo
docker compose --env-file /secure/geoscan-demo/compose.env \
  -f build/geoscan-mvp/compose.yaml up --build -d
```

Bootstrap создаёт роли `viewer`, `planner`, `admin`, отдельные пароли БД и
локальные сертификаты. Доступы находятся в приватном `credentials.txt`.
Для внешнего сервера замените origin и сертификат на доверенный; подробности
в [инструкции эксплуатации](docs/operations.md). Секреты не входят в Git.
Для текущего сервера с systemd и
nginx см. [docs/deploy.md](docs/deploy.md): push **не обновляет** запущенный
релиз автоматически. Работающий адрес на момент описания:
[https://45.87.246.124/](https://45.87.246.124/).

Демонстрация: [docs/demo.md](docs/demo.md). Форматы и проверка: [data/SCHEMA.md](data/SCHEMA.md),
[docs/verify.md](docs/verify.md). Контракт модулей: [docs/contract/H1_H2.md](docs/contract/H1_H2.md).

в них версиям; их наличие не означает повторного прохождения всех тестов
текущим снимком.
