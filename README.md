# Geoscan Mission Planner

Сервис планирования съёмки группой беспилотников. Принимает зоны работ,
рельеф, площадки, состав БВС и ограничения; строит галсы, распределяет их
между аппаратами, планирует вылеты и дозарядки, проверяет безопасность и
экспортирует полётные задания.

**[Работающий сервис](https://45.87.246.124/)** — вход без пароля.
**[Пояснительная записка](docs/submit-note.md)** ·
**[Руководство пользователя](docs/user-guide.md)** ·
**[Архитектура и алгоритм](docs/current-planning.md)**

Два критерия оптимизации: время завершения всей миссии и суммарный налёт.
В интерфейсе есть 20 готовых шаблонов: S00–S09 — простые тесты,
S10–S19 — сложные примеры с рельефом. Результаты можно выгрузить в KML,
GeoJSON, JSON, PDF и DOCX; KML/GeoJSON — также отдельно для каждого БВС.

## Локальный запуск

Проверяемая платформа — **Linux x86-64, Python 3.12**; в Windows используйте
WSL2 с Ubuntu 24.04. Нужны Git и интернет для установки зависимостей.
Node.js, Docker, PostgreSQL и доступ к другим репозиториям для этого способа
не нужны: интерфейс и исходники всех модулей уже включены.

На Ubuntu 24.04 установите системные зависимости:

```bash
sudo apt-get update
sudo apt-get install -y git python3.12 python3.12-venv fonts-dejavu-core libgomp1 libexpat1 ca-certificates
```

Затем:

```bash
git clone https://github.com/ImmortalDR/geoscan-mission-planner.git
cd geoscan-mission-planner
python3.12 scripts/install.py
bash scripts/run_local.sh
```

Откройте **http://127.0.0.1:8090/** и введите код, который напечатает скрипт.
В локальном режиме код создаётся случайно при каждом старте; для постоянного
кода задайте переменную `GMP_ACCESS_CODE`. Остановка — `Ctrl+C`, повторный
запуск — `bash scripts/run_local.sh`. Сервер слушает только локальный адрес.

Первый расчёт:

1. Нажмите **«Открыть…»**, выберите простой шаблон **S00**.
2. Запустите расчёт из панели параметров запуска. Шаблон уже сохранён;
   для расчёта не нужно создавать копию. Если изменили его — используйте
   **«Сохранить как…»**.
3. Посмотрите покрытие, граф, маршруты и итоговую метрику. После успешной
   проверки скачайте результат на вкладке экспорта.

Интерактивная документация API: [http://127.0.0.1:8090/docs](http://127.0.0.1:8090/docs).
Проверка готовности: `curl http://127.0.0.1:8090/health/ready`.

### Данные и повторный запуск

Сценарии, расчёты, SQLite и журналы сохраняются в `artifacts/h3_workspace/`.
Этот каталог не входит в Git. Для отдельного чистого рабочего пространства:

```bash
GMP_DATA_DIR="$PWD/artifacts/new-workspace" bash scripts/run_local.sh
```

После установки можно считать включённые сценарии без интернета:

```bash
GMP_OFFLINE=1 bash scripts/run_local.sh
```

В этом режиме отключены внешние подложки карты и загрузка отсутствующего
рельефа. Включённые GeoTIFF и расчётные модули работают локально.
Для обычного режима интернет нужен только для внешних карт и получения
Copernicus DEM, когда пользователь выбрал эту загрузку.

Если установка не удалась, установщик укажет каталог журнала. Проверьте
Python 3.12, наличие пакета `python3.12-venv` и доступ к индексу Python.
Если порт 8090 занят, выберите другой: `GMP_PORT=8091 bash scripts/run_local.sh`.
Диагностика библиотек: `.venv/bin/python scripts/doctor.py`.

## Проверки

Из корня репозитория после установки:

```bash
.venv/bin/python data/run_dataset.py verify --integrity
.venv/bin/python scripts/validate_h1_h2_contract.py
.venv/bin/python scripts/run_regression.py --output artifacts/verification
```

Первые две команды сверяют эталоны, контрольные суммы данных и контракт
модулей. Третья запускает тесты API, планировщика, покрытия и независимых
проверок. Отчёты записываются отдельно от исходников.
PostgreSQL-тесты пропускаются, если не задан `GMP_TEST_DATABASE_URL`;
используйте только одноразовую БД с именем, оканчивающимся на `_test`.
CI запускает эти тесты с отдельным PostgreSQL.

Условия и результаты проверок: [docs/verify.md](docs/verify.md).
Исторические измерения в [docs/evidence/](docs/evidence/) относятся к
указанным там версиям и не заменяют новый запуск тестов.

## Состав репозитория

| Каталог | Назначение |
| --- | --- |
| `src/gmp/` | API, адаптеры, независимые проверки, хранение и экспорт |
| `h1/h1_coverage/` | Построение покрытия и галсов |
| `h2/src/h2/` | Граф, OR-Tools Routing, расписание и разведение БВС |
| `web/h3/` | Готовый интерфейс и библиотеки с лицензиями |
| `data/` | 12 базовых сцен, 14 эталонных пар вход/выход, рельеф и атрибуция |
| `src/gmp/scenario_templates/` | Дополнительные шаблоны; вместе с `data/` дают 20 примеров интерфейса |
| `tests/`, `h1/.../tests/`, `h2/tests/`, `fixtures/`, `datasets/` | Тесты и используемые ими наборы данных |
| `algorithms/`, `examples/`, `generators/` | Описание методов, примеры и воспроизведение тестовых данных |
| `scripts/`, `deploy/`, `.github/` | Установка, проверки, развёртывание и CI |
| `docs/` | Документация, контракты и отобранные протоколы проверок |

H1/H2 включены обычными файлами, **без submodules**. Рабочие БД,
пользовательские загрузки, виртуальные окружения, секреты и промежуточные
серверные файлы в поставку не входят.

## Серверное развёртывание

Для локальной проверки достаточно инструкции выше. Для отдельного сервера
предусмотрены Docker Compose с PostgreSQL/nginx/TLS и systemd:

- [Docker и эксплуатация](docs/operations.md).
- [Развёртывание через systemd](docs/deploy.md).
- [Состав и упаковка поставки](docs/PUBLICATION.md).

Серверные секреты генерируются при развёртывании, в репозитории их нет.
Публичный вход основного сайта включён отдельной настройкой; локальный
запуск и корпоративный профиль по умолчанию требуют авторизацию.
