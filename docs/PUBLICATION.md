# Публичная поставка Geoscan Mission Planner

Публикуется самостоятельный снимок интегрированного `h3/`: его содержимое
становится корнем нового репозитория. H1 и H2 включены обычными файлами.
Рабочий `/root` и его Git-историю не публикуем: в них есть файлы домашнего
каталога, настройки инструментов и учётные данные. `.gitignore` не удаляет
уже отслеживаемые файлы и не очищает историю.

## Что входит

| Путь в публичном репозитории | Назначение |
| --- | --- |
| `README.md` | Описание и локальный запуск для эксперта |
| `src/`, `web/`, `h1/`, `h2/` | Код H1, H2, H3 и готовый интерфейс |
| `requirements.txt`, `requirements.lock`, `pyproject.toml` | Зависимости и метаданные Python |
| `scripts/`, `deploy/`, `.github/` | Установка, запуск, проверки, шаблоны деплоя и CI |
| `tests/`, `fixtures/`, `datasets/`, `data/` | Тесты, исходные сцены, DSM, эталонные ответы, манифесты и атрибуция |
| `docs/`, `algorithms/`, `examples/`, `generators/`, `handoff/`, `DEMO_PATH.md`, `README_H3.md` | Архитектура, алгоритмы, инструкции, измеренные отчёты и история интеграции |
| `.gitignore`, `.gitattributes`, `PUBLIC_MANIFEST.json` | Правила Git и контрольные суммы поставки |

DSM (`*.tif`), GeoJSON/KML, эталонные JSON, иллюстрации, JUnit XML и
необходимые архивы наборов **оставляем**. Это входы и доказательства, а не
случайный мусор. Лицензии и атрибуция сторонних данных находятся в
`data/sources/`, информация о других наборах — рядом с ними; лицензии
встроенных библиотек интерфейса — в `web/h3/vendor/`.
Новая общая лицензия на код автоматически не назначается: это решение авторов.

## Что не входит

- Старая `.git/`, `.gitmodules` и ссылки на отдельные репозитории модулей.
- `.env`, коды доступа, `ACCESS.txt`, `credentials.txt`, файлы пользователей,
  пароли/DSN, приватные ключи, сертификаты и каталоги секретов.
- Рабочие БД, сессии, загрузки пользователей, резервные копии, `artifacts/`.
- `.venv`, кэши Python/pytest, сборки, служебные журналы, настройки IDE,
  переписка агентов, `.ssh`, `.codex`, история shell и чужие проекты.
- Исследовательская библиотека PDF из родительского H1, внутренний бэклог
  родительского репозитория и незавершённые материалы презентации.

Документация для поля формы: `docs/reviewer-guide.md` и `docs/architecture.md`.
Презентация и скринкаст сдаются отдельными ссылками после финализации.
Секреты стенда передаются отдельно от открытого репозитория.

## Подготовка чистого каталога

Из интегрированного исходного репозитория:

```bash
python3 scripts/prepare_public_repo.py /tmp/geoscan-public
```

Скрипт копирует только отслеживаемые файлы и явно перечисленные новые файлы
подготовки; локальные изменения этих файлов включаются. Произвольные
неотслеживаемые файлы не включаются. Он отказывается перезаписывать каталог,
проверяет выходы symlink за пределы поставки, подозрительные имена файлов,
известные форматы токенов/приватных ключей и ограничивает размер одного файла.
Это ограниченная автоматическая проверка, а не гарантия отсутствия любого
возможного секрета. Манифест фиксирует фактический состав и SHA-256.
Ни Git-история, ни remote, ни серверное состояние не копируются.

## Публикация

Создайте **пустой Public** репозиторий на GitHub под аккаунтом команды,
без автоматически создаваемого README, лицензии и `.gitignore`.
Подготовленный каталог должен быть отдельным репозиторием:

```bash
cd /tmp/geoscan-public  # или фактический каталог подготовленной поставки
git init -b main
git add .
git diff --cached --stat
git ls-files --stage   # не должно быть строк с режимом 160000 (submodule)
git commit -m "Prepare Geoscan Mission Planner submission"
# Замените OWNER/REPO реальными значениями:
git remote add origin https://github.com/OWNER/REPO.git
git push -u origin main
```

Эти команды выполняются **только в подготовленном каталоге**, не в `/root`.
Локальный коммит/отправка требуют обычной настройки имени автора и доступа
к выбранному GitHub-аккаунту. Скрипт подготовки не делает push автоматически.

После отправки откройте страницу репозитория без авторизации. Затем
клонируйте HTTPS-ссылку в новый каталог без submodules и выполните README:
установку, локальный запуск, проверку датасета и контракта. Проверьте статус
GitHub Actions; существующие отчёты не заменяют новый запуск CI.
В поле «Репозиторий» формы вставьте URL корня репозитория, не ссылку на файл
или отдельный коммит. После стоп-кода 29.09.2026 23:59 МСК сданную ссылку
не обновлять согласно командному `SUBMIT.md`.
