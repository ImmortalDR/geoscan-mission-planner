# Текущий алгоритм и соответствие заданию Геоскана

Актуально для исходников 29.09.2026. Первичный документ — «Сервис планирования
и распределения беспилотных авиационных работ», техническое задание 2026,
разделы 2–5 и 7; дополнительные допущения — Q&A заказчика 16.09.

## Расчёт

H1 строит покрытие областей из требований датчика, GSD, перекрытия, ветра
и ограничений, выбирает направление. H2 получает контракт `gmp.h1_h2.v3`:
каждый полный галс — обязательная задача с двумя направлениями. Геометрия
галса неизменяема; соседние галсы одной зоны могут исполняться разными БВС.

RoutingGraph строит направленные варианты галсов, связи по краям зон,
дополнительные граничные точки не реже 300 м, связи каждой штатной базы
со всеми такими точками, разреженные межзональные связи. Реальные базы не
соединяются напрямую. Таблицы переходов, времени, ресурса и возврата
различаются по физическому профилю БВС. Dummy-узлы выбирают разрешённый старт
и финиш; копии зарядных узлов позволяют несколько вылетов одного аппарата.
Штатный финиш исключает reserve; аварийная достижимость их учитывает.

Старт выбирается из компактных вариантов соседних полос/змеек, с жадным
запасным вариантом. Затем OR-Tools Routing применяет Guided Local Search.
Наши улучшения упорядочивают и обменивают целые блоки галсов, подбирают
направления и зарядки. Несколько лучших кандидатов проверяются подробно;
конфликты разводятся задержками на земле. При временных запретах также
пробуется последовательное выполнение оставшихся галсов по разрешённым окнам.
Последовательные транзитные участки сокращаются лишь после проверки нового
перелёта. Финальные времена вычисляются по подробной траектории.

Один пользовательский режим, фиксированный seed 20260918, один поток поиска.
Глубокий бюджет — верхнее ограничение, с ранним остановом на простых сценах
и при отсутствии улучшений. CP-SAT и старый отжиг остались как исторические
альтернативы, но не являются текущим LIVE-путём. Технические подробности
и изменения параметров — `h2/docs/routing.md` в исходном репозитории.

Независимый H3 повторно проверяет полное покрытие, сегменты и растровые
ячейки, запреты, временные ограничения, непрерывное сближение, ресурс,
площадки, обслуживание, датчики и метрики. Ошибка поиска не считается
доказательством INFEASIBLE. Сертификат связывает точный результат с входами.

## Время работ

В `mission.json` поддерживаются `preparation_time_s` и `data_download_time_s`,
неотрицательные секунды (в API до 86400), по умолчанию 0 для прежних входов.
Пусть T0/T1 — пересечение окна миссии и светового окна. Вылеты выполняются
между T0 + preparation и T1 − download. Подготовка всей группы параллельная;
снятие данных начинается после последней посадки. Это явная упрощённая
модель наземных работ, без очереди операторов и пропускной способности каналов.

`makespan_s = last_landing − T0 + data_download_time_s`; подготовка уже
включена через отложенный старт. `total_flight_s` — сумма длительностей
вылетов от начала взлёта до завершения посадки. Наземные этапы не расходуют
полётный ресурс. `flight_completion_s` показывает время до последней посадки.
Постоянный завершающий этап не меняет ранжирование кандидатов Routing,
но ограничивает доступное окно и входит в окончательную метрику H3.

## Соответствие

| Требование PDF | Реализация |
|---|---|
| Браузер, произвольные площадки, флот и области | Web-редактор, загрузка файлов, API |
| RGB, мультиспектр, ИК, LiDAR, геофизика | Профили датчиков, совместимость, галсы |
| Скорость, заряд, ветер | Индивидуальные параметры; ресурс по времени, резерв, ветер и направление галсов |
| Воздушное пространство, NFZ, резервные площадки | Входные слои, построение и независимая проверка |
| Два критерия | makespan / total_flight, проверенные сценовые прогоны |
| Полные индивидуальные KML/GeoJSON | [Схема v2](flight-export.md), время/высоты/скорость/этапы/площадки, фильтр БВС |
| Визуализация, выбор критерия, демонстрация | Каталог из 20 примеров, карта и расписание |
| Архитектура, алгоритм, запуск, API, руководство, ограничения | README, architecture, этот документ, /docs, user-guide, safety |

Реализованные проверки не являются допуском к реальным полётам, моделью
полной аэродинамики или гарантией глобального оптимума. Качество дискретных
фотокадров и перекрытия отдельно не сертифицируется. Общая численная проблема
траекторий ровно на границах DEM, замеченная при создании S18, остаётся
известным ограничением; H3 в таком случае отклоняет несогласованные высоты.

Артефакты проверок имеют дату и хеши. Старые 450 тестов/нагрузочные замеры
относятся к указанному в них релизу и не заменяют проверку текущего изменения.
Отправка ссылок на платформу, доступ экспертов и окончательная презентация
проверяются отдельно; существование файлов не означает, что они уже сданы.
