# CONTRACT H1 ↔ H2 — AtomicTask Pipeline Gate

**Статус:** жёсткий контракт. Нарушение = ошибка валидации / запрет merge до исправления.
**Шов:** выход H1 → вход H2.  
**Версия схемы:** `gmp.h1_h2.v1`  
**Код-источник полей:** `h3/src/gmp/models.py`  
**Дата:** 2026-09-19

---

## 0. Зачем это существует

H1 и H2 работают параллельно на фикстурах. Единственная точка стыка — **этот контракт**.  
Менять алгоритм внутри H1 или H2 можно свободно. Менять форму/смысл полей ниже — **нельзя** без `contract`-PR и апрува обоих владельцев.

Правило для людей и агентов:

> Если правка ломает `scripts/validate_h1_h2_contract.py` (или эквивалентный pytest) — правка невалидна, даже если «так удобнее».

---

## 1. Единица обмена

H1 отдаёт H2 **один артефакт** — JSON-конверт:

```text
H1H2Bundle
```

Путь фикстур (стабильные имена):

```text
fixtures/h1_h2/
  <scene_id>.bundle.json          # полный конверт
  <scene_id>.tasks.json           # опц. только tasks (должен проходить тот же schema)
```

Подмена «fake → real» = замена файла с тем же `schema_version` и теми же обязательными полями. Код H2 не ветвится на «fake/real».

## 2. JSON Schema (норматив)

### 2.1. Корень `H1H2Bundle`

| Поле | Тип | Обязательно | Кто пишет | Кто читает |
|------|-----|-------------|-----------|------------|
| `schema_version` | string | да | H1 | H2 reject если ≠ `gmp.h1_h2.v1` |
| `scene_id` | string | да | H1 | H2 |
| `crs` | object | да | H1 | H2 |
| `generated_at` | ISO-8601 string | да | H1 | audit |
| `source` | `"coverage"` \| `"fixture"` \| `"synthetic"` | да | H1 | H2 (не влияет на логику) |
| `fleet` | `UavWire[]` | да | H1 (из Scene) | H2 |
| `sites` | `SiteWire[]` | да | H1 | H2 |
| `mission` | `MissionWire` | да | H1 | H2 |
| `tasks` | `AtomicTaskWire[]` | да | H1 | H2 |
| `feasibility` | object | да | H1 | H2 |
| `coverage_meta` | object | нет | H1 | H2 может игнорировать |
| `warnings` | string[] | да (может `[]`) | H1 | H2 не должен падать |

### 2.2. `crs` (жёстко)

```json
{
  "metric_epsg": 326XX,
  "axis": "ENU_metres",
  "note": "Все координаты tasks/sites в метрической CRS сцены, НЕ в lon/lat"
}
```

**Инварианты CRS**

1. Все `x,y` в `tasks` и `sites` — **метры** одной metric CRS.  
2. H2 **запрещено** перепроецировать геометрию задач.  
3. WGS-84 только на границах IO (вне этого контракта).  
4. Смена EPSG = новый `scene_id` или bump `schema_version` (не тихая подмена).

### 2.3. `AtomicTaskWire` (ядро контракта)

Соответствует `models.AtomicTask`. Поля ниже — **frozen**.

| Поле | Тип | Смысл | Инвариант |
|------|-----|--------|-----------|
| `id` | string | уникальный id задачи | уникален в `tasks[]`; стабилен между прогонами при том же seed |
| `job_id` | string | родительский survey job | непустой |
| `payload_class` | string | класс съёмки | ∈ {`rgb`,`multispectral`,`thermal`,`lidar`,`geophysics`,`rgb_video`} |
| `payload_profile_id` | string | профиль нагрузки | непустой |
| `agl_m` | number | рабочая высота AGL, м | `>= 40` (MIN_SAFE_AGL_M) |
| `transects` | TransectWire[] | галсы внутри задачи | `len >= 1` |
| `survey_length_m` | number | сумма длин галсов | `> 0`; ≈ sum(transect.length_m) ±1e-3 |
| `turn_count` | int | число разворотов между галсами | `>= 0` |
| `sweep_angle_deg` | number | угол галсов | любое finite |
| `entry` | `[x,y]` | вход в задачу | = start первого трансекта |
| `exit` | `[x,y]` | выход | = end последнего трансекта |
| `geom_coords` | `[x,y][]` | полилиния задачи | `len >= 2`; непрерывна |
| `internal_transition_m` | number | переходы между галсами внутри task | `>= 0` |
| `fixed_wing_safe` | bool | H1 уже проверил turn buffer vs NFZ | H2 может фильтровать fixed-wing |
| `notes` | string[] | опц. пояснения | не влияют на feasibility |

#### `TransectWire`

| Поле | Тип | Инвариант |
|------|-----|-----------|
| `coords` | `[x,y][]` | `len >= 2` |
| `length_m` | number | `> 0`; ≈ длина полилинии ±1e-3 |
| `job_id` | string | = `AtomicTask.job_id` |

**Запрещено в AtomicTaskWire (агентам и людям):**

- добавлять обязательные поля без bump `schema_version`;
- удалять/переименовывать поля выше;
- класть lon/lat в `coords` / `entry` / `exit`;
- хранить время старта задачи (это зона H2);
- хранить `uav_id` назначения (назначение делает только H2);
- дублировать геометрию в двух CRS.

Опциональные **additive** поля разрешены только в namespace:

```text
extensions.<owner>.*
```

пример: `extensions.h1.maneuver_buffer_m`.  
H2 **обязан игнорировать** неизвестные `extensions.*` (не падать).  
H2 **не имеет права** требовать `extensions.*` для корректной работы MVP.

| Поле | Тип | Инвариант |
|------|-----|-----------|

| `model` | string | |
| `uav_class` | `fixed_wing` \| `multirotor` \| `vtol` | |
| `ground_speed_ms` | number | `> 0` |
| `operational_endurance_min` | number | `> 0` |
| `max_wind_ms` | number | `>= 0` |
| `payload_classes` | string[] | непустой |
| `energy_reserve_fraction` | number | `0..0.5` |
| `horizontal_separation_m` | number | `> 0` |
| `vertical_separation_m` | number | `> 0` |
| `turnaround_buffer_m` | number | `>= 0` |
| `start_site` | string \| null | если задан — id ∈ sites |

### 2.4.1. MVP: обязательные модели БВС (продуктовый инвариант)

**Не путать со схемой одного bundle:** в конкретном `fleet[]` может быть один борт (smoke).  
**Путать нельзя с «любые строки в `model`»:** для MVP H1 и H2 **обязаны** поддерживать целевую линейку Geoscan ниже (KB + solver + фикстуры приёмки).

#### Канонические значения `UavWire.model`

| `model` (канон) | Отображаемое имя | Примечание |
|-----------------|------------------|------------|
| `geoscan_201` | Geoscan 201 | целевой профиль MVP |
| `geoscan_401` | Geoscan 401 | целевой профиль MVP |
| `geoscan_701` | Geoscan 701 | целевой профиль MVP |
| `geoscan_801` | Geoscan 801 | целевой профиль MVP |
| `geoscan_gemini` | Geoscan Gemini | целевой профиль MVP |

Инварианты MVP:

1. **UAV Knowledge Base (зона H1)** содержит seed-профили для всех пяти `model` выше (числа + provenance). Добор до «≥10 профилей» из ТЗ v4 — аддитивно; внешние аппараты только как `reference` / test, без заявления hardware-совместимости Geoscan.
2. **H1** умеет выгрузить любой из этих профилей в `fleet[]` / feasibility без спец-веток «неподдерживаемая модель».
3. **H2** принимает bundle с любым подмножеством этих `model` и не падает / не игнорирует борт только из‑за имени модели.
4. **Сюит приёмки** (не каждый smoke-файл) включает сценарии, где в `fleet` встречаются все пять канонических моделей (можно распределить по разным `scene_id`).
5. Другие строки в `model` **разрешены** (синтетика, VRPTW-адаптеры, reference). Они не отменяют обязанность поддерживать пятёрку Geoscan.
6. Смена канонических id (`geoscan_201` → другое) = правка этого контракта + апрув H1+H2; **без** обязательного bump `schema_version`, пока поля `UavWire` не меняются. Рекомендуется отметить в Changelog.

Источник продуктового требования: `docs/reference/spec.md` §6.

### 2.5. `SiteWire`

| Поле | Тип | Инвариант |
|------|-----|-----------|
| `id` | string | уникален |
| `x`,`y` | number | метры CRS |
| `role` | `both` \| `start` \| `landing` \| `reserve` | |
| `candidate` | bool | default false |

Инвариант сцены: существует ≥1 site с `can_start` и ≥1 с `can_land` (role учитывается как в `models.Site`).

### 2.6. `MissionWire` (только то, что нужно H2)

| Поле | Тип | Инвариант |
|------|-----|-----------|
| `objectives` | string[] | каждый ∈ {`makespan`,`total_flight`} — **только эти два в MVP** |
| `window_start` / `window_end` | ISO-8601 \| null | если оба заданы: start < end |
| `wind.speed_ms` | number | `>= 0` |
| `wind.direction_deg_from` | number | |
| `allow_different_start_end` | bool | |
| `require_complete_coverage` | bool | default true |
| `require_schedule` | bool | default true |

`MAX_QUALITY` / `BALANCED` **вне контракта v1**. Появление = новый schema_version или отказ валидатора.

### 2.7. `feasibility` (обязательный мост)

H1 обязан отдать матрицу совместимости, чтобы H2 не угадывал GIS-логику:

```json
{
  "eligible_uav_ids_by_task": {
    "jobA#T000": ["uav1", "uav2"],
    "jobA#T001": ["uav2"]
  },
  "ineligible_reasons": {
    "jobA#T001:uav1": "payload_class_mismatch"
  }
}
```

**Инварианты**

1. Для каждого `task.id` ключ в `eligible_uav_ids_by_task` существует.  
2. Список может быть пустым → H2 помечает задачу невыполнимой / план INFEASIBLE, **не** молча дропает без статуса.  
3. Каждый uav id ∈ `fleet`.  
4. H2 **не пересчитывает** payload/wind eligibility заново как источник истины; может только ужесточать (например energy), но не расширять eligible set.

## 3. Семантические гарантии H1 (обещания)

H1 гарантирует для каждого bundle со `source=coverage` (для fixture/synthetic — те же геометрические инварианты, кроме покрытия 100%):

| ID | Гарантия |
|----|----------|
| G1 | Геометрия задач не пересекает hard NFZ (линии галсов). |
| G2 | `entry`/`exit`/`geom` согласованы с `transects`. |
| G3 | `survey_length_m > 0`, полилинии валидны. |
| G4 | `agl_m` согласован с payload profile. |
| G5 | `fixed_wing_safe=false` ⇒ fixed-wing не в eligible (или eligible пуст для FW). |
| G6 | Ids задач уникальны и детерминированы при фиксированном seed. |
| G7 | `schema_version` = `gmp.h1_h2.v1`. |

H2 **имеет право верить** G1–G7 без повторного GIS-coverage.  
Повторная проверка — зона H3 Safety, не H2.

## 4. Семантические права и обязанности H2

| ID | Правило |
|----|---------|
| R1 | H2 не меняет геометрию `AtomicTask` (не двигает coords). |
| R2 | H2 может reverse task (`path_coords(reverse=True)`), не меняя файл bundle. |
| R3 | H2 назначает `uav_id`, порядок tasks, sorties, timestamps. |
| R4 | Objective только из `mission.objectives` ∩ {`makespan`,`total_flight`}. |
| R5 | Каждая task из bundle с nonempty eligible либо назначена, либо явно в `unassigned`/`INFEASIBLE` отчёте. |
| R6 | H2 не пишет обратно в `fixtures/h1_h2/*.bundle.json` (выход H2 — отдельный Plan contract). |
| R7 | При несовпадении `schema_version` — hard fail, без «best effort». |

## 5. Что считается нарушением контракта (авто-reject)

Валидатор обязан падать, если:

1. Нет / неверный `schema_version`.  
2. Пустой `tasks` при `require_complete_coverage=true` и `source=coverage`.  
3. Дубликат `task.id` / `uav.id` / `site.id`.  
4. Координаты выглядят как lon/lat эвристика (`|x|<=180` и `|y|<=90` на всех точках при metric_epsg UTM) — **warn→fail** в strict mode.  
5. `entry`≠start первого трансекта или `exit`≠end последнего.  
6. `survey_length_m` расходится с суммой трансектов > 1 м.  
7. Feasibility ссылается на несуществующие id.  
8. Обязательное поле удалено или переименовано.  
9. В PR изменён `models.AtomicTask` без bump версии и без обновления этого файла.

## 6. Процедура изменения контракта

```text
1. Ветка: contract/h1-h2-vN
2. Обновить этот файл + models.py + JSON Schema + фикстуры
3. Апрув owner H1 И owner H2
4. Bump schema_version (gmp.h1_h2.v2, …)
5. Старые bundle с v1 остаются валидны до sunset date в changelog
6. Без пунктов 3–4 merge запрещён (Integration Owner)
```

Агенту в промпте зона H1/H2 всегда добавлять:

```text
FORBIDDEN: change H1H2Bundle schema, AtomicTask required fields, or fixtures/h1_h2 schema_version
without explicit contract PR instructions.
```

## 9. Граница с H3 (чтобы не расползлось)

| Артефакт | Owner | H1/H2 |
|----------|-------|-------|
| `H1H2Bundle` | H1 пишет, H2 читает | этот файл |
| `Plan` / sorties / waypoints | H2 пишет | **отдельный** contract H2↔H3 |
| Safety Certificate | H3 | H2 не выдаёт SAFE |

H2 может класть в Plan черновой `status`, но authoritative SAFE/UNSAFE — только H3.

## 10. Коротко для чата команды

> H1 и H2 стыкуются только через `H1H2Bundle` schema `gmp.h1_h2.v1`: метрические `AtomicTask[]` + fleet + sites + feasibility.  
> Геометрию задач H2 не меняет. Назначение БВС делает только H2.  
> MVP-флот: KB и пайплайн поддерживают `geoscan_201|401|701|801|gemini` (§2.4.1); в одном bundle может быть подмножество.  
> Любое новое обязательное поле = новый schema_version + апрув обоих.  
> Фикстура и live coverage — один формат; подмена файла не ломает solver.
