# Где тестировать сложный H2

Короткий указатель для владельца H2: что открывать на сайте и что гонять локально.

## Термины (H3 кабинет)

| Термин | Значение |
|--------|----------|
| **Сценарий** | Неизменяемый шаблон из датасета `h3/data/scenarios/S*` |
| **Проект** | Рабочая копия команды: правки, версии, live-расчёт, экспорт |

Клик по сценарию в каталоге **создаёт проект**. Не путать с H2 viewer (там «сценарий» = готовый `H1H2Bundle`).

## Что на сайте H3 (порт 8443)

Каталог специально помечает групповые сцены и поднимает их наверх.

| ID | БВС | Зачем H2 |
|----|-----|----------|
| **S01_msu_100km2** | 4 | Эталон масштаба ~100 км², оба objective |
| **S11_payload_compatibility** | 5 | Разнородный флот / payload |
| **S05_multi_uav** | 2 | Согласование двух бортов |
| Остальные с 1 БВС | 1 | Ограничения (ветер, NFZ, отказ, multi-sortie одного борта) — **не** stress assignment |

1 БВС в карточке ≠ «задача упростилась»: suite заказчика — в основном oracle ограничений.

## Где сильнее multi-UAV (локально / H2 viewer)

Bundles на входе оптимизатора (`gmp.h1_h2.v1`):

```text
h2/fixtures/*.bundle.json          # то, что крутит H2 viewer на :443
h1/fixtures/h1_h2/*.bundle.json    # канон H1 (синхронизировать в h3/fixtures)
```

| Bundle | БВС | Задачи (порядок) | Заметка |
|--------|-----|------------------|---------|
| `S01_full_customer_acceptance_100km2` | **10** | ~110–196 | Главный stress для продвинутых алгосов |
| `S02_multipolygon_holes` | 3 | десятки | Геометрия + группа |
| `S03_temporal_airspace_daylight` | 4 | десятки | Время + группа (есть в `h2/fixtures`) |
| `S05_4d_deconfliction` | 2 | мало | Конфликты / ladder |
| `S09_wind_feasibility` / `S11_…` | 5 | десятки | Feasibility / payload |

H2 viewer в шапке показывает `N задач, M БВС`; список сортируется с multi-UAV сверху, по умолчанию открывается S01.

```bash
# H2 viewer
cd h2 && python3 viewer/server.py --host 127.0.0.1 --port 8090

# E2E
cd h2 && python3 scripts/e2e_acceptance.py
```
