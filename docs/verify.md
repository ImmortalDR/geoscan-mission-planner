# Воспроизводимые проверки

Все команды выполняются из корня репозитория после установки по
[README](../README.md). Они используют включённые H1/H2 и данные,
не требуют работающего основного или тестового сервера команды.

```bash
.venv/bin/python scripts/doctor.py
.venv/bin/python data/run_dataset.py verify --integrity
.venv/bin/python scripts/validate_h1_h2_contract.py
.venv/bin/python scripts/run_regression.py --output artifacts/verification
```

- `doctor` проверяет импорт нативных библиотек и показывает ресурсы среды.
- `verify --integrity` проверяет 14 эталонных пар, сертификаты и SHA-256 данных.
- Валидатор контракта проверяет включённые H1↔H2 bundles.
- Регрессия охватывает безопасность, API, инфраструктуру, property-тесты,
  отчёты, H1 и H2. JSON и JUnit записываются в `artifacts/verification/`.

PostgreSQL-тесты требуют `GMP_TEST_DATABASE_URL` на отдельную одноразовую БД
с суффиксом `_test`; её таблицы очищаются. Без переменной тесты пропускаются.
Проверки запускаются вручную; автоматические GitHub Actions не используются.

Для проверки браузера с Playwright и текущего набора сценариев используйте
`web/tests/`; для проверки поднятого сервиса — `scripts/smoke_h3_service.py`
и `scripts/verify_h3_live.py` (параметры доступны через `--help`). Такие
проверки создают рабочие сценарии и результаты: запускайте их на отдельной
локальной установке или тестовом пространстве.

Сертификаты эталонов и результаты живой оптимизации — разные проверки.
Корректный новый маршрут не обязан совпадать с эталоном или быть глобально
оптимальным. Нагрузочные измерения также относятся к указанному железу,
числу пользователей и выбранным сценариям.

[Сохранённые протоколы](evidence/README.md) описывают конкретные прежние прогоны.
Очистка конкурсной поставки не меняет расчётные исходники; её отдельный
контрольный прогон описан в `evidence/submission/`.

Браузерный smoke `web/tests/reviewer_smoke.py` по умолчанию проверяет и карту.
На среде без рабочего WebGL можно отдельно проверить роли и документацию
с `GMP_BROWSER_SKIP_WEBGL=1`; отчёт явно отметит пропуск карты. Этот режим
не заменяет стандартную графическую проверку.
