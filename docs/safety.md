# H3: границы и доказательства проверки

Основания: [рабочее ТЗ v4, §17](sources/docs/reference/spec.md)
и [ответы Geoscan от 16.09.2026, раздел 3](sources/CUSTOMER_QA_20260916.md).
Рабочее ТЗ v4 является детализацией постановки команды, а не новым документом производителя.

Авторитетный шлюз: `gmp.safety.h3_gate.validate_result`. Проверяющее ядро
`h3_core` не импортирует optimizer, H1, H2, planner или их вычисленные показатели.
Внешние траектории представлены линейными сегментами XYZ/AMSL/UTC; `phase`
и `job_id` конечной точки описывают входящий сегмент. Координаты внешних
данных WGS84, расстояния вычисляются в указанной метрической проекции.

## Соответствие §17

| Требование | Независимая проверка и ограничение | Негативный тест |
| --- | --- | --- |
| 100% required coverage | Объединение физических полос сенсора пересекается с исходными полигонами каждого задания, включая MultiPolygon и отверстия. Запреты не вырезаются из обязательного задания. | `test_dataset_fractional_tolerance_does_not_allow_partial_service_mission`, `test_coverage_gap_and_false_metric_are_independent` |
| NFZ | Пересечение всего XY-сегмента с постоянной запретной геометрией, включая границу. | `test_no_fly_crossing_between_waypoints` |
| Allowed airspace | Разрешённая геометрия должна содержать весь XY-сегмент, включая точки взлёта и посадки. | `test_allowed_airspace_hole_is_checked_between_waypoints` |
| Obstacle clearance | Пространственные интервалы пересечения с footprint + horizontal buffer; высота препятствия + vertical buffer сравнивается с AGL на каждом пересечённом пикселе DEM. | `test_obstacle_is_checked_between_waypoints`, `test_zero_buffer_point_obstacle_is_not_erased`, `test_raster_cell_grazing_is_checked_between_regular_samples` |
| Temporal airspace | Пересечение интервалов пространства, UTC и линейного AMSL, а не только проверка waypoints. Только запретные интервалы; неизвестный тип или AGL-система временных ограничений отклоняется. | `test_active_time_and_altitude_crossing_between_waypoints`, `test_same_zone_at_nonoverlapping_time_passes` |
| Separation | Аналитический минимум горизонтального расстояния на совместном временном/вертикальном интервале; пороги берутся как максимум требований двух БВС. | `test_continuous_crossing_detected_without_waypoint_coincidence`, `test_crossing_at_different_times_is_safe` |
| Per-sortie resource | Полная длительность от начала взлёта до конца посадки не превосходит endurance × (1 - reserve). Время не выводится из заявленного summary. | `test_resource_reserve_is_enforced` |
| Reserve | Резерв вычитается до полёта; remaining endurance каждой точки сравнивается с доступным ресурсом минус прошедшее время. Ветер не меняет расход. | `test_reserve_and_remaining_claim_protect_landing_suffix` |
| Reserve landing reachability | Проверенный остаток текущего маршрута до разрешённой основной посадки является конструктивным свидетельством достижимости из любой точки, с учётом оставшегося ресурса. Отдельная прямая через NFZ не используется как доказательство. | `test_reserve_and_remaining_claim_protect_landing_suffix`, `test_wrong_site_role_fails` |
| Fixed-wing maneuver zones | На поворотах направления более 5° рядом с survey-сегментом проверяется круг turnaround buffer против NFZ и allowed airspace. Это договорная защитная зона, не модель динамики самолёта. | `test_fixed_wing_buffer_checks_a_zone_the_route_does_not_enter` |
| Start/end feasibility | Роли и назначение площадок; конечная точка не далее 1 м от площадки и у поверхности; окна миссии/светового дня, время обслуживания, отсутствие переноса БВС между площадками без полёта. | `test_wrong_site_role_fails`, `test_daylight_window_and_ground_endpoint_are_checked`, `test_aircraft_service_interval_is_enforced`, `test_aircraft_cannot_teleport_between_different_sites` |
| Payload compatibility | Тип задания равен типу профиля и присутствует в списке допустимых нагрузок исполняющего БВС; GSD выводится из камеры и максимального фактического AGL сегмента. | `test_used_aircraft_payload_compatibility_is_rechecked`, `test_job_type_cannot_be_replaced_with_incompatible_payload` |

Дополнительно проверяются лимит ветра, скорость, минимальный AGL, заявленные
дистанции/времена/покрытие, обязательные поля, конечность чисел, timezone и
известные идентификаторы. Взлёт/посадка могут быть ниже minimum AGL только
в объявленном коридоре площадки; фаза не может маскировать низкий перелёт.
Поверхность проверяется на границах и внутри всех пересечённых ячеек, а не
только с регулярным шагом 20 м. Допуск AGL берётся из явно сохранённой политики.

## Покрытие и точность

Неизменённый датасет допускает `coverage_tolerance_fraction = 0.001`, то есть
99.9%. Это не буквальные 100%: на 100 км² такой допуск позволил бы пропустить
100 000 м². Поэтому сервисный шлюз дополнительно требует полное покрытие
каждого задания, допуская только площадь численной ошибки
`max(0.001 м², required_area_m2 * 1e-12)`. Эта политика записывается в сертификат.
Тест с реальным зазором 2 м², проходящий исходный порог 99.9%, шлюз отвергает.
Все 11 SAFE-эталонов фактически полные; наибольший остаток порядка 0.0000011 м².

Полоса опирается на минимальный AGL сегмента и геометрию камеры; для лидара
и геофизики используется явно объявленная ширина `line_spacing_m`.
Дискретные фото, продольное/боковое перекрытие кадров, закрытие обзора рельефом
в стороне от траектории, динамика БВС, реальные разрешения и глобальный
оптимум не доказаны. Это явно указано в сертификате и PDF/DOCX, а не скрыто
за статусом SAFE. DSM не выдаётся за точную актуальную модель голой земли.

`makespan_s` включает ожидание от эффективного начала окна до последней
посадки и заданное снятие данных. Подготовка сдвигает первый допустимый
взлёт, снятие данных резервирует конец окна. Между вылетами учитывается
обслуживание. Поля `preparation_time_s` и `data_download_time_s` по умолчанию
равны 0 для прежних входов; отсутствие явных значений отмечено в метриках.
Наземные работы не расходуют полётный ресурс. [Модель времени](current-planning.md).

## Достижимость посадки

Ответ Geoscan требует достижимости хотя бы одной основной или временной
площадки из каждой точки; резервные площадки не используются штатно.
Если весь оставшийся путь до основной посадки уже проверен по ограничениям,
а расход линейный по времени и весь вылет укладывается в доступный ресурс,
то его суффикс из любой промежуточной точки удовлетворяет тому же пределу.
Это сильнее дискретной проверки только контрольных точек, но относится к
номинальной модели: отказ двигателя, внезапная погода или изменение режима
в середине миссии не моделируются. Возможность отдельного аварийного
манёвра к другой площадке не заявляется.

## Статусы и воспроизводимость

- `SAFE`: все независимые проверки пройдены, сертификат привязан к SHA-256
  всех 11 входных файлов, включая DEM, и точного JSON результата.
- `UNSAFE`: маршрут, вход или его утверждения не прошли проверку. Таймаут,
  пустой ответ и неполное эвристическое решение не доказывают невозможность.
- `INFEASIBLE`: проверено необходимое условие невозможности: нет совместимого
  БВС, все совместимые исключены ветром, либо даже оптимистическая нижняя
  граница перелёта до всей обязательной области и обратно больше ресурса
  каждого пригодного БВС. Safety Certificate для полёта не выдаётся.

Изменение входа/результата в ходе проверки отклоняется. Старая модель
`Scene/Plan` проверяется через снимок текущего состояния, не перечитыванием
исходной директории: это важно для изменённых рекомендаций. Перед выдачей
старого API-сертификата повторно проверяется актуальность снимка.
Рекомендации проходят новый расчёт и тот же шлюз для изменённого входа;
непроверенные предложения не маркируются подтверждёнными.

Генератор `gmp.recommend.proposals` предлагает до 8 детерминированных изменений:
известную другую базу/старт/посадку, разные start/end, совместимую замену
или дополнительный БВС из снимка каталога, более поздний старт после окончания
временного запрета внутри исходного окна. Наличие нового оборудования явно
является допущением. Резервные площадки не становятся штатными, NFZ, GSD,
покрытие, погода и запас ресурса не ослабляются. API ограничивает число
реальных перепланирований, хранит только повторно проверенные SAFE-варианты;
выбор пользователя обязателен. Новые площадки без исходных координат,
расширение окна за объявленные границы, новый день/погода и ослабление съёмки
не предлагаются автоматически: это новые исходные условия, не доказанные
данными текущей сцены.

Проверка из каталога проекта:

```bash
PYTHONPATH=src:../h1/h1_coverage/src .venv/bin/python -m pytest tests/safety tests/report -q
```

Тесты создают собственные маленькие
аналитически проверяемые сцены, а не сверяются только с готовыми маршрутами.
