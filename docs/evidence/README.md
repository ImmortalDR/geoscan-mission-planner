# Протоколы проверок

Здесь оставлены отобранные измерения; промежуточные снимки интерфейса,
сравнения экспериментальных вариантов и журналы старых развёртываний убраны.
Отчёты не загружаются в рабочее пространство как пользовательские сценарии.

| Материал | Область и ограничения |
| --- | --- |
| `submission/` | Проверка самостоятельной конкурсной поставки после очистки; состав и условия — в её README |
| `tz-compliance/` | 29.09.2026: экспорт, наземные работы, площадки, живые S18/S19; исходный релиз указан в отчёте |
| `system.json`, `system.junit.xml` | Историческая общая регрессия: 450 успешных тестов; не считать проверкой текущего снимка |
| `algorithms/` | Исторические CSV/JSON по отдельным методам; сверяйте записанные хеши исходников |
| `load/` | Нагрузка на указанном оборудовании; не моделирует 32 одновременных тяжёлых расчёта |
| `compose.json`, `compose-runtime.json` | Предыдущая проверка изолированного Docker Compose/PostgreSQL/TLS |
| `production-api.json` | Предыдущий HTTPS-прогон API |
| `security/dependencies.json` | Аудит зависимостей на дату отчёта; не обещание отсутствия будущих уязвимостей |

Новые результаты записывайте в `artifacts/`, как показано в
[инструкции проверок](../verify.md). Включение нового отчёта в исходники —
отдельное осознанное действие. Существующие измерения не подменяют
повторный прогон у конкретного коммита.
