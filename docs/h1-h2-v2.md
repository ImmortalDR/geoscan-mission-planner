# H1 ↔ H2: варианты змейки

## v2 — две змейки (26.09.2026)

Изменение H1/H2 явно разрешено Тимофеем. Текущий экспорт H1:
`gmp.h1_h2.v2`; H2 в `/root/h3/h2` принимает v1 и v2. Старые v1
фикстуры остаются неизменными и поддерживаются без установленной даты sunset.
Standalone `/root/h2` остаётся потребителем v1; рабочая реализация v2 — в h3.

Все прежние обязательные поля сохраняются и описывают основной маршрут.
Новое обязательное поле задачи `route_variants` содержит:

- `primary`: исходную змейку без изменений;
- `alternate`: тот же порядок галсов, но координаты каждого галса развёрнуты.
  Соединения — прямые от конца текущего галса к началу следующего.

При одном галсе передаётся только `primary`. Каждый элемент содержит `id`,
`geom_coords`, `internal_transition_m`, `fixed_wing_safe`. H1 проверяет
самолётные манёвры отдельно для второй змейки. Матрица eligibility не расширяется.
H2 выбирает только переданный вариант и направление его полного обхода,
не перестраивая ни галсы, ни соединения. Получаются четыре кандидата для
нескольких галсов и два для одного. Географически запрещённые варианты и
небезопасные для fixed-wing исключаются; четыре кандидата не означают четыре
допустимых полёта. Финальный SAFE по-прежнему устанавливает H3.

В H2 Plan у каждого вылета `task_variants` (`primary`/`alternate`) и
`task_reversed` параллельны `task_ids`. Старый план без `task_variants`
означает `primary`. Независимая проверка H2 сверяет точки и минимальную
длительность именно выбранного варианта. H3 получает фактическую траекторию
и эти признаки в экспорте. Текущий выбор остаётся по длине входного перелёта;
совместная оптимизация входа и выхода и кеширование участков — отдельная работа.

При фиксированных задаче, БПЛА, варианте, направлении, DEM и настройках
относительная траектория внутри задачи детерминирована. Начало полёта,
внешние перелёты и конфликты расписания в этот независимый участок не входят.
