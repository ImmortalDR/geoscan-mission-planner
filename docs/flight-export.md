# Форматы полётных заданий

Рабочий endpoint: `GET /api/v1/plans/{plan_id}/export?format=kml|geojson`.
Необязательный `uav_id` выбирает все вылеты одного аппарата; без него
выгружается вся группа. Неизвестный/неиспользованный аппарат — HTTP 422.
В интерфейсе выбор находится на вкладке «Экспорт». JSON, PDF, DOCX и
сертификат всегда относятся к полной миссии.

Маршрутный экспорт разрешён только для SAFE с сертификатом. Перед выдачей
сверяются хеши исходных файлов, результата и сертификата. Изменённый или
неполный план экспортируется лишь как диагностический JSON/отчёт.

## Содержимое

Схема `geoscan.flight-export.v2`. Каждый вылет содержит его идентификатор,
`uav_id`, порядковый `index`, `start_site`, `landing_site`, `task_ids`,
`t_start`, `t_end` и остальные рассчитанные атрибуты вылета.
Все исходные точки сохраняются в исходном порядке без округления:

| Поле | Значение |
|---|---|
| `waypoint_index` | Номер с нуля внутри вылета |
| `lon`, `lat` | Долгота, широта WGS84, градусы |
| `amsl_m` | Абсолютная высота, метры, вертикальная основа исходного DEM |
| `agl_m` | Высота над поверхностью DEM, метры |
| `t` | ISO 8601 с часовым поясом |
| `speed_ms` | Скорость, м/с |
| `phase` | `takeoff`, `transit`, `survey`, `landing`, `loiter`, `wait` |
| `job_id` | Зона съёмки либо `null` |
| `remaining_endurance_s` | Оставшееся разрешённое полётное время, секунды |
| `sortie_id`, `uav_id` | Принадлежность точки вылету и аппарату |
| `start_site`, `landing_site` | Идентификаторы площадок вылета |

Для точки с индексом >0 `phase`, `job_id`, `speed_ms` описывают входящий
сегмент от предыдущей точки. Между точками модель использует линейную
интерполяцию XYZ и времени. Это формат планирования и обмена; команды
автопилота, частота съёмки отдельных кадров и динамика самолёта не кодируются.

`context` содержит параметры миссии, выбранных БВС, датчиков, геометрию
используемых площадок, критерий, режим расчёта, метрики, хеши и ограничения.
Метрики и хеш исходного результата всегда относятся ко всей миссии, даже
при фильтре одного БВС (`metrics_scope`, `certificate_scope`). Фильтр не
создаёт отдельный сертификат и не изменяет заверенный результат.

## GeoJSON

WGS84 `FeatureCollection`. На вылет — одна `LineString` с `feature_type=sortie`,
и отдельная `Point` на каждую точку (`feature_type=waypoint`). Третья координата
— AMSL в метрах, как заявлено в `units`; это намеренная прикладная конвенция,
а не обещание эллипсоидальной высоты RFC 7946. Поля AGL/AMSL продублированы
явными атрибутами точек, поэтому вертикальная основа не теряется.
Старым потребителям, ожидавшим только линии, нужно фильтровать `feature_type`.

## KML

KML 2.2: Document → папка БВС → папка вылета → линия и папка точек.
Линия имеет TimeSpan, точка — TimeStamp, геометрия — `altitudeMode=absolute`.
Параметры хранятся в ExtendedData/Data/value. Строки записываются как строки,
числа, списки, объекты, булевы значения и null — как JSON. XML-символы экранируются.
Стандартный просмотрщик показывает линии; точки по умолчанию выключены,
чтобы тысячи значков не закрывали карту, и доступны в дереве слоёв.
Совместимость с импортом команд конкретного автопилота не заявляется.

Проверки: `tests/api/test_flight_export.py` сравнивает каждое значение после
разбора обоих форматов, несколько аппаратов/вылетов, спецсимволы и фильтр.
API-тесты проверяют привязку к сертификату, запрет UNSAFE и повреждённого плана.
