# Редактор сценариев и запусков H1

## Открытие и сохранение

В интерфейсе две папки: **Шаблоны** (12 исходных S00–S11 и 6 авторских S12–S17) и
**Мои сценарии**. Отдельного понятия проекта нет.

- Откройте сценарий, измените «Сцену» и «БВС».
- **Переименовать** меняет имя пользовательского сценария сразу, сохраняя ID,
  расчёты и несохранённые изменения входных данных. Шаблоны переименовывать нельзя.
- **Сохранить** обновляет текущий пользовательский сценарий в списке.
- **Сохранить как…** открывает поле с именем «старое имя — копия». Его можно
  изменить перед сохранением. Подтверждение создаёт независимый сценарий.
  Исходные данные и расчёты исходного сценария не меняются.
- Все шаблоны допускают только **Сохранить как…**. Защита действует
  также в API и сохраняется при редактировании рабочего снимка шаблона.
- «Создать с нуля» открывает пустую сцену без БВС.
- Сохранение допускает незавершённый сценарий. Расчёт требует валидного входа.

В разделе «Области съёмки и датчики» у каждой области есть выбор датчика из
общего каталога, независимо от оборудования БВС. В свойствах выбранной области
доступно то же поле «Датчик этой области»; оно задаёт вид съёмки;
профиль оборудования выбирается того же типа. Для нескольких датчиков на
одной территории есть «Дублировать область».

Сохранение не скачивает рельеф: если геометрия выходит за имеющийся DSM,
сохраните сценарий, нажмите «Обновить DSM», затем сохраните его снова.
Старт с несохранёнными правками считает рабочий снимок, но не перезаписывает
сохранённый сценарий автоматически.

В заголовке каждого БВС есть кнопки копирования и удаления. Копия получает имя
`<имя>_copy1`, `<имя>_copy2` и т. д. с первым свободным номером и независимую
копию всех параметров. Кнопка «Добавить» создаёт новый БВС. Сохраняется лимит
10 БВС в сценарии. Копирование и удаление поддерживают отмену.

Для старта и посадки БВС можно закрепить конкретную площадку или выбрать
**«Любая площадка»**. Во втором случае в сценарии сохраняется `null`, а H2
выбирает подходящую некандидатную площадку при построении маршрута. Для старта
допустимы роли `start` и `both`; для посадки — `landing`, `both` и
`reserve`. Запрет разных точек старта и финиша в параметрах миссии имеет
приоритет и требует возврата на стартовую площадку.

## Отмена правок

**Ctrl+Z** — отменить, **Ctrl+Y** или **Ctrl+Shift+Z** — повторить.
Также доступны кнопки со стрелками. История включает до 100 состояний
геометрии, добавления/удаления областей, датчиков, БВС и параметров миссии.
Изменение поля фиксируется при выходе из него; горячая клавиша также фиксирует
текущее поле перед отменой. Сохранение текущего сценария не сбрасывает историю.
Открытие другого сценария и перезагрузка страницы начинают новую историю.
В JSON-диалоге действует текстовая отмена браузера, а после «Применить» изменение
попадает в общую историю. Невведённый до конца полигон можно отменить через Escape.
**Ctrl+S** сохраняет, **Ctrl+Shift+S** открывает «Сохранить как»; для шаблона
Ctrl+S также предлагает новое имя.

## Расчёты и логи

Во вкладке **«Запуск»** показаны наличие и статус расчёта, его код с кнопкой
**«Копировать код»**, а также кнопки запуска и остановки. В списке сценариев
код не показывается: успешно рассчитанный сценарий отмечен «завершен».

Запуск доступен только для сохранённого сценария без несохранённых правок.
Иначе кнопка отключена и просит сначала нажать «Сохранить» или «Сохранить как».
Шаблон перед запуском нужно сохранить как свой сценарий. Автосохранения при запуске нет.
«Запустить расчёт» последовательно выполняет H1, H2 и H3. «Обзор» показывает
прогресс всех этапов, «Галсы и задачи» — выход H1, «Маршруты» — расписание и
траектории H2, «Проверки» — результат независимой проверки H3. Нажатие на
задачу усиливает её подсветку. После H3 во вкладке «Экспортировать результат»
доступны отчёт и полный JSON; маршрутные форматы доступны для статуса SAFE.
«ОСТАНОВИТЬ РАСЧЁТ» отменяет очередь либо принудительно завершает процесс.
После обновления страницы последний расчёт снова доступен.

Каждый полный запуск получает код, например `RUN-20260925-012345abcdef`.
Код показан во вкладке «Запуск», в заголовке результата и в обзоре. Передайте его в чате, чтобы
найти конкретный вход и результаты конвейера. Папка временных логов:

```
${GMP_DATA_DIR}/tmp/runs/<код запуска>/
    scenario.json       # исходная сцена, БВС, датчики, имя, ID и хеш входа
    run.json            # код, статус, этапы, ошибки, число задач и галсов
    h1_h2.bundle.json   # точный bundle gmp.h1_h2.v1 после успешного H1
```

Корень можно изменить через `GMP_RUN_LOG_DIR`. Абсолютный путь и ссылки на
скачивание файлов показаны в «Обзоре». Снимок `scenario.json` содержит путь к
исходному каталогу с DSM; сам бинарный GeoTIFF повторно в лог не копируется.
Отменённый или упавший запуск имеет `run.json` с соответствующим статусом;
несуществующий результат H1 не подменяется пустым успешным bundle.

Во вкладке «Запуск» виден код и статус последнего расчёта. Если хеш входных данных изменился, явно указано, что расчёт
относится к другим данным. «Сохранить как» создаёт независимый сценарий без
чужих расчётов. При несохранённых правках остаётся виден код прежнего расчёта.

## Хранение и API

Исходные шаблоны: `data/scenarios/S*/input/`.
Авторские: `src/gmp/scenario_templates/S*/input/` (в Git и составе приложения).
Каталог объединяет оба источника; редактор их не изменяет. S12–S17 доступны
после деплоя с пустым рабочим пространством, без копирования локальной SQLite.
Описание снимков: [scenario_templates/README.md](../src/gmp/scenario_templates/README.md).
Пользовательские данные: `GMP_DATA_DIR/scenes/<id>/input/` и
`GMP_DATA_DIR/workspace.sqlite3`. По умолчанию — `artifacts/h3_workspace`.
Перезапуск должен использовать тот же `GMP_DATA_DIR`.

Сохранённый сценарий имеет `saved=true`, `expires_at=null`. `library_id`
связывает снимки одного сценария; только один виден в пользовательском списке.
Старые снимки и несохранённые черновики сохраняют прежний срок хранения 30 дней.
Исходные данные прежнего интерфейса не удаляются при обновлении.

API: `GET /api/v1/scenes?saved_only=true`, `POST /api/v1/scenes/{id}/save`,
`POST /api/v1/scenes/{id}/save-as` с `{ "name": "Новое имя" }`.
Логи: `GET /api/v1/plans/{id}/log/{filename}`; доступ требует авторизации.

## Проверки

`tests/api/test_h3_workspace.py`: сохранение и перезапуск, защита шаблонов,
независимый Save As, устаревший результат после правок, точное совпадение bundle
в логе с результатом, остановка процесса и отмена очереди.

`scripts/smoke_scenario_ui.py`: Save/Save As, перезагрузка, Ctrl+Z/Ctrl+Y для
полей, датчика, добавления/удаления и перемещения геометрии, БВС; отмена после
сохранения; коды запуска, скачивание bundle, заглушки и остановка.
Требуются Playwright + Chromium, `GMP_ACCESS_CODE` и при необходимости
`GMP_SMOKE_URL`. Скрипт удаляет только созданные им тестовые сценарии.

H2 сначала рассматривает все задачи, затем использует остаток бюджета для
улучшения маршрутов. Ограничения ресурса одного вылета и окна миссии сохраняются.
Во вкладке «Маршруты» неполный план помечается явно; раскрываемый список показывает
неназначенные задачи и причины, включая минуты ресурса и выход за окно миссии.
