# Реализация маршрутизации H2

Текущая постановка и ограничения описаны в
[алгоритме сервиса](../../docs/current-planning.md).
Интеграционный API использует OR-Tools Routing; предыдущие реализации
сохранены для совместимости и отдельных регрессионных тестов.

## Основные этапы

1. H1 передаёт галсы. Адаптер формирует `gmp.h1_h2.v3` с направлениями
   прохождения каждого полного галса и совместимостью датчиков/БВС.
2. H2 строит граф обслуживания и перелётов, предрасчитывает стоимость и
   расход ресурса для типов БВС. Базы учитывают старт, финиш и промежуточные
   зарядки; резервные площадки используются для аварийной достижимости.
3. Компактные начальные решения предпочитают последовательные локальные
   галсы. Routing и дополнительные перестановки/обмены блоков улучшают
   время завершения миссии либо суммарный налёт.
4. Несколько кандидатов подробно пересчитываются. Временные ограничения и
   конфликты обрабатываются сдвигами расписания; предусмотрена работа по
   разрешённым окнам. Фиксированный seed обеспечивает воспроизводимый поиск.
5. Результат передаётся независимому H3. Экспорт полётных заданий разрешён
   только после проверки и выдачи сертификата SAFE.

## Навигация по коду

| Модуль в `h2/src/h2/` | Назначение |
| --- | --- |
| `routing_graph.py` | Граф галсов, межзональных переходов и баз |
| `routing_solver.py` | Модель OR-Tools Routing |
| `routing_seed.py`, `routing_blocks.py` | Начальные решения и улучшения блоков |
| `routing_planner.py`, `routing_windows.py` | Выбор/проверка кандидатов и временные окна |
| `transit.py` | Расчёт перелётов с ограничениями |
| `deconfliction.py` | Проверка конфликтов и временное разведение |
| `checks.py` | Внутренние проверки результата H2 |

Из корня репозитория после установки:

```bash
.venv/bin/python -m pytest -c pyproject.toml h2/tests/test_routing.py -q
```
