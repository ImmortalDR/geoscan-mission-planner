# Быстрая оценка фиксированного плана H2

`h2.fixed_estimator.FixedPlanEstimator` готовит таблицы один раз для сцены,
затем оценивает заданные назначения БПЛА, базы, вылеты, порядок задач,
варианты змейки, направления и времена старта. На этих таблицах работает
[отжиг H2](annealing.md), подключённый к кнопке расчёта сайта. Сам метод
`evaluate` не меняет заданный план автоматически.

## Модель

Для каждого **полного профиля БПЛА** (модель, скорости, ресурс, времена,
радиус разворота и остальные параметры) рассчитываются совместимые варианты
задач. У задачи с несколькими галсами их четыре, с одним — два.
Одинаковые профили двух физических БПЛА используют общие таблицы,
но назначения, закреплённые базы и обслуживание проверяются отдельно.

Геометрия съёмки остаётся из H1. Каждый вариант проходит подробную дискретизацию
рельефа и расчёт времени по той же модели, что `Scheduler.move`: горизонтальное
движение, изменение абсолютной высоты и время разворотов. Высота съёмки не
увеличивается ради запаса, чтобы не ухудшать заданный GSD.

Для перелётов используется сетка с восемью соседями, по умолчанию 100 м.
Рёбра и присоединение концов задач проверяются целиком по геометрии запретов,
а рельеф вдоль них семплируется с шагом не больше половины ячейки DEM и
`sample_step_m`. Таким образом, сетка поиска 100 м не превращает DEM в карту
с разрешением 100 м. За пределами DEM и в NoData проходы запрещаются.

По умолчанию заложены:

- множитель **1,25** для суммы горизонтального времени и времени изменения
  высоты; сумма консервативнее одновременного выполнения этих движений;
- вершина высотного профиля перелёта **на 30 м выше** максимума высот входа,
  выхода и крейсерской высоты; старт и конец соединяются с точными высотами задач;
- горизонтальный буфер запретов **10 м**, дополнительно к радиусу разворота самолёта;
- **60 секунд** дополнительного запаса на аварийный возврат сверх штатного
  энергетического резерва из входных данных;
- время поворотов самолёта на выбранном пути и запас на неизвестные граничные
  курсы, в том числе для возвращения по дереву ближайших баз.

Временные запретные зоны для перелётов и аварийных возвращений считаются
постоянными. Это намеренно может отбрасывать допустимые в отдельные часы пути.
Для пересекающей такую зону съёмки учитывается всё окно выполнения задачи,
без использования разрешённых высотных прослоек. Невозможность найти путь в
консервативной сетке не доказывает невозможность полёта в исходной сцене.

## Ресурс для возможности возвращения

Один поиск от виртуального узла посадки строит стоимость возвращения для всех
узлов сетки к любой разрешённой посадочной/резервной площадке. Учитываются
положение площадки и посадка. Закрепление обычной базы БПЛА не запрещает аварийную
посадку на другую разрешённую площадку — это соответствует текущей политике H2.

Для задачи запоминается порог оставшегося ресурса в секундах:

`required_start = max по точкам (время от начала задачи + возврат из точки + запас)`.

Промежуток между соседними точками покрывается возможностью продолжить полёт
до следующей точки и вернуться оттуда. Для выбранного сеточного перелёта
аналогично используется максимум по префиксам пути; весь избыток времени
над горизонтальным полётом консервативно включается в каждый префикс. Это
сохраняет запас при распределении задержки вдоль подробной траектории. Порог сравнивается с ресурсом,
оставшимся к началу этого фрагмента. Последняя посадка также входит в ресурс.
Ресурс здесь остаётся временной моделью H2, а не моделью электрической батареи.

Для всех концов задач заранее строятся матрицы расстояний и деревья путей.
При первой оценке конкретного перехода из дерева извлекается выбранный путь,
считаются повороты и порог возврата; результат затем кэшируется. Дорогой
подробный прогон перелёта не повторяется для каждого назначения.

## Интерфейс

Установка дополнительных зависимостей в изолированное окружение:

```bash
python -m pip install -e '/root/h3/h2[estimate]'
```

Зависимости NumPy/SciPy теперь входят в установку H2. На этом сервере они
есть в `/root/.venv` и отдельном окружении dev-службы на 9443. Рабочая служба
на 443 использует прежнее окружение.

```python
from h2.fixed_estimator import FixedPlanEstimator
from h2.scheduler import Settings

estimator = FixedPlanEstimator(bundle, scene_sidecar,
    Settings(sample_step_m=20, survey_speed_factor=1.0))
first = estimator.evaluate(fixed_plan)
second = estimator.evaluate(another_fixed_plan)  # те же подготовленные таблицы
selected = estimator.materialize(fixed_plan)    # подробная траектория + проверки H2
```

`survey_speed_factor` должен соответствовать профилям датчиков сцены, как в
штатном адаптере H3; у S17 он равен 1.0. Остальные параметры модели также должны
совпадать с настройками расчёта, который требуется оценить.

Формат входного плана:

```json
{
  "schema_version": "h2.fixed_plan.v1",
  "sorties": [{
    "uav_id": "U01",
    "start_site_id": "BASE",
    "landing_site_id": "BASE",
    "task_ids": ["task1", "task2"],
    "task_variants": ["primary", "alternate"],
    "task_reversed": [false, true],
    "start_s": 0
  }]
}
```

Если `start_s` отсутствует, используется первое свободное время этого БПЛА
после предыдущего вылета и обслуживания. Список задаёт порядок вылетов каждого
БПЛА; разные БПЛА могут работать одновременно. Отсутствующие варианты означают
`primary`, направления — `false`. Задачи нельзя терять, дублировать или назначать
несовместимому БПЛА. Проверяются роли и непрерывность баз, ресурс, ветер,
обслуживание, окно миссии, переданное `scene.operating_window` (световой день)
и заданные `Settings.task_windows`.

CLI из `/root`:

```bash
PYTHONPATH=h3/h2/src:h3/src:h3/h1 .venv/bin/python -m h2 estimate \
  bundle.json --scene scene.json --fixed-plan fixed-plan.json \
  --survey-speed-factor 1 --out /tmp/fixed-estimate
```

Файлы результата: `preparation.json`, `estimate.json`. Опция `--materialize`
добавляет `detailed/plan.json`, GeoJSON и HTML. Коды возврата CLI: 0 — оценка
допустима, 2 — оценка отвергнута, 1 — ошибка входа/зависимостей. Повторный запуск
CLI повторяет подготовку; для массовой оценки нужно сохранять объект в Python.

Новый объект нужен после изменения сцены, DEM, парка БПЛА или настроек.
Отпечаток учитывает содержимое DEM, а не только путь к файлу.

## Что подтверждает оценка

Статус `ESTIMATED_FEASIBLE` относится к проверенным ограничениям оценки.
Он **не является SAFE**. `ESTIMATE_REJECTED` тоже не является доказательством
невозможности исходной задачи: может мешать заданный план или запас сеточной модели.

Межбортовые конфликты, непрерывная проверка поверхности между точками,
покрытие исходных зон и GSD остаются за независимой проверкой. Дневное окно
учитывается оценщиком, если оно передано в sidecar; H3 проверяет его независимо.
Сетка не моделирует динамику сглаженного самолётного разворота. Численные
запасы снижают риск недооценки, но не доказывают безопасность для любого DEM.
Перед принятием выбранный план разворачивается через `materialize`, экспортируется
через `gmp.api.h2_adapter.export_sorties` и проходит штатный H3. При разворачивании
время перелёта сохраняет консервативную оценку; если подробное движение требует
больше, это явно записывается в `estimate_overruns`, и план не получает FEASIBLE.

На S00 подробный план прошёл H3. На S05 одновременные вылеты были допустимы
по быстрой ресурсной оценке, но H2/H3 обнаружили конфликт. Тот же состав задач
с явно заданным последовательным стартом прошёл H3 SAFE. Это проверяется
регрессионным тестом, а не скрытым исправлением расписания оценщиком.

## Воспроизводимый замер S17

```bash
cd /root
PYTHONPATH=h3/h2/src:h3/src:h3/h1 .venv/bin/python \
  h3/h2/scripts/benchmark_fixed_estimator.py --out /tmp/s17-fixed-benchmark
```

Скрипт запускает H1, подготовку таблиц, 100 повторов одного плана, 100 разных
заданных планов и сравнивает 1000 перелётов с подробной моделью движения.
`--bundle` позволяет исключить H1 из замера. По умолчанию используются исходные
файлы шаблона `S17_MSU_geo401_RGB_and_Lidar_alotofZones`. Его внутренний `scene_id`
в исходном JSON — `S01_msu_100km2`; это не подмена сценария.

Измерение 26.09.2026: **117 задач, 384 галса, 3 БПЛА, 2 полных профиля,
452 совместимых направленных варианта задач**. Обе матрицы вместе имеют
148 194 ячейки, включая базы, диагонали и переходы внутри одной задачи.
Подробные числа и SHA-256 исходной сцены находятся в
[`../../docs/evidence/fixed-estimator-s17.json`](../../docs/evidence/fixed-estimator-s17.json).

Итоговый контрольный замер: H1 4,30 с; подробные задачи 0,42 с; сетки и поля
возврата 0,69 с; пороги возврата задач 1,46 с; матрицы переходов 3,13 с;
вся подготовка оценщика 5,76 с; первая оценка 0,113 с.
От входа до первой оценки — **10,20 с** (без импорта Python-модулей).
Новый заданный план: среднее 0,042 с, 95-й перцентиль 0,055 с,
максимум среди 100 планов 0,110 с. Повтор того же плана — в среднем 0,0035 с.
Это измерения на текущем сервере, не пределы для любой сцены/машины.

В 1000 сравнений с подробным движением по **тем же выбранным путям**
недооценок времени не было: минимальное отношение оценки ко времени модели —
1,34, медианное — 1,63. Сравнение не подтверждает отсутствие конфликтов или
полную безопасность S17 в H3.

Контрольные назначения намеренно фиксированы и не оптимизировались.
Все 100 случайных полных планов были отвергнуты. В демонстрационном плане
с одной задачей на вылет длительность 41,9 часа при окне 11,5 часа, также есть
нарушения ресурса. Это измерение скорости оценки **неудачных планов**, а не
обещание готового допустимого решения S17.
