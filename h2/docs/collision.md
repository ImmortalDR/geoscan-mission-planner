# Ограничение на столкновение БПЛА в H2

Проверено по исходникам и тестам 21.09.2026. Документ описывает именно
`h2`, а не другой оптимизатор из `h3`.

## 1. Требование ТЗ и решения реализации

Источники:

- [ТЗ, §15 — 4D Deconfliction](../docs/reference/spec.md):
  после построения расписания проверяются пары траекторий `p(t)=(x,y,z)`
  с горизонтальной и вертикальной сепарацией, зависящей от типа аппарата.
  Collision avoidance обязателен. Финальный checklist требует zero final 4D conflicts.
- [ТЗ, §12](../docs/reference/spec.md): fixed-wing требует большей
  separation zone; обычный hover для fixed-wing запрещён.
- [Контракт H1–H2, §2.4](docs/contract/H1_H2.md): каждый аппарат передаёт
  положительные `horizontal_separation_m` и `vertical_separation_m`.
- [Роль H2, §3.2](docs/process/roles.md): детектор, resolver и проверка
  S05-подобного сценария относятся к H2. Итоговая safety-проверка — к H3.

ТЗ требует сепарацию, но не выписывает точную формулу объединения порогов двух
аппаратов и граничные неравенства. Правила `max`, строгое `<` и линейная
интерполяция ниже — **реализованные соглашения H2**, а не дословные требования ТЗ.
Их следует согласовать с H3.

## 2. Точное условие конфликта

Для двух разных БПЛА A и B:

```text
H = max(A.horizontal_separation_m, B.horizontal_separation_m)
V = max(A.vertical_separation_m,   B.vertical_separation_m)

horizontal(t) = sqrt((xA(t) - xB(t))² + (yA(t) - yB(t))²)
vertical(t)   = abs(zA(t) - zB(t))

КОНФЛИКТ существует, если есть общий активный момент t, в котором:
    horizontal(t) < H  И  vertical(t) < V
```

Следовательно, для допустимого взаимного положения достаточно:

```text
horizontal(t) >= H  ИЛИ  vertical(t) >= V
```

Это нарушение защитного интервала, а не только физический контакт корпусов.
Пороги не складываются. Это не расстояние в 3D по сфере и не требование
обязательно выдерживать оба интервала одновременно.

Пример: если H=300 м, V=50 м:

| Горизонталь | Вертикаль | Проверка сепарации |
|---:|---:|---|
| 100 м | 20 м | Конфликт |
| 350 м | 20 м | Нет конфликта |
| 100 м | 60 м | Нет конфликта |
| 300 м | 20 м | Нет конфликта: равенство допустимо |
| 100 м | 50 м | Нет конфликта: равенство допустимо |

Эти примеры не подтверждают остальные ограничения полёта: например, смена
высоты может быть запрещена требованиями съёмки.

### Откуда берутся числа

Источником являются поля аппарата в конкретном bundle, а не таблица,
зашитая в детектор. Среди текущих 12 fixtures встречаются:

| model во входе | Горизонталь, м | Вертикаль, м |
|---|---:|---:|
| geoscan_201 | 300 | 50 |
| geoscan_701 | 300 | 50 |
| geoscan_401_geo | 50 | 50 |
| geoscan_801 | 50 | 50 |
| geoscan_gemini | 50 или 300 в разных входах | 50 |

Это значения текущих сценариев, не универсальные паспортные нормативы моделей.
Для пары аппаратов с горизонтальными порогами 50 и 300 м применяется 300 м.

## 3. Какая траектория проверяется

- Координаты x/y — локальные метрические координаты; время `t_s` — секунды
  относительно общего начала миссии.
- Между соседними waypoints x/y/z линейно интерполируются по времени.
- Высота берётся из `z_m` (AMSL). Если поле отсутствует, используется `agl_m`:
  это допустимо только как упрощение с общим плоским уровнем земли.
  Одинаковый AGL над разным рельефом не означает одинаковый AMSL.
- Проверяются интервалы между waypoints, а не только положения в отдельных
  точках и не только кадры анимации. Детектор аналитически решает неравенства
  расстояний для относительного линейного движения.
- Пересекаются интервалы нарушения горизонтального и вертикального порогов.
  Нарушения в разные моменты времени не образуют конфликт.
- Общая активная конечная/начальная точка двух сегментов проверяется даже
  при пересечении временных диапазонов ровно в один момент.
- Сегмент исключается, если обе его точки имеют фазу `ground` или `service`.
  Взлёт и посадка не исключены; это также означает консервативную занятость
  общей площадки в модели scheduler.
- У одного физического БПЛА запрещено положительное временное перекрытие
  двух вылетов независимо от расстояния между ними: `same_uav_overlap`.
  Дополнительные требования обслуживания проверяются отдельно.

Неконечные координаты/время, убывание времени и фактическое перемещение за
нулевое время отклоняются. При нулевой длительности допускается лишь шум
координат до 1e-9 м. Это допуск корректности траектории, не запас сепарации.

## 4. Где находится проверка

| Файл / функция | Назначение |
|---|---|
| [src/h2/deconfliction.py](src/h2/deconfliction.py), `detect_conflicts(sorties, fleet)` | Основной детектор: пороги пары, интервалы конфликтов, одновременные вылеты одного БПЛА |
| Там же, `_segments`, `_position`, `_inside_interval` | Валидация сегментов, интерполяция, аналитическое решение неравенств |
| [src/h2/checks.py](src/h2/checks.py), `check_plan` | Повторно вызывает `detect_conflicts`; добавляет нарушение с кодом `conflict` |
| [src/h2/planner.py](src/h2/planner.py), `plan_bundle` | Проверка до/после resolver и условия выдачи FEASIBLE |
| [src/h2/deconfliction.py](src/h2/deconfliction.py), `resolve_conflicts` | Изменяет расписание для устранения конфликтов; это не сам детектор |

Прямой вызов:

```python
from h2.deconfliction import detect_conflicts

conflicts = detect_conflicts(plan['sorties'], bundle['fleet'])
assert conflicts == []
```

Каждая запись конфликта содержит ID вылетов и аппаратов, `required_h_m`,
`required_v_m`, `start_s`, `end_s`, `min_horizontal_m` и `kind`.
Границы интервала могут соответствовать равенству порогу; не следует считать
весь закрытый интервал строгим нарушением. Соседние интервалы объединяются
для отчёта. Минимум горизонтального расстояния не является минимумом 3D.

В результате плана доступны `deconfliction.before`, `deconfliction.remaining`,
`checks.violations` и `metrics.conflict_count`. Последняя метрика считает
записи конфликтов, а не столкнувшиеся аппараты или число пересечений карты.

`FEASIBLE` требует отсутствия оставшихся конфликтов, назначения всех задач
и прохождения проверок. Отключение resolver не отключает проверку.
`FEASIBLE` не означает SAFE: H2 всегда требует проверки H3.

Важно: финальная проверка H2 повторно использует **тот же детектор**.
Это отдельный проход проверки плана, но не независимая реализация collision
detector. У H3 есть собственный путь проверки в другом проекте; его
эквивалентность этой формуле сквозным тестом здесь не доказана.

## 5. Что сейчас делает resolver

`resolve_conflicts` применяет **ground shift**: менее приоритетный вылет и его
downstream сдвигаются до конца другого вылета (+1e-6 с); интервалы обслуживания
сохраняются. Если окно миссии блокирует сдвиг, конфликт остаётся явным.

Воздушное ожидание и изменение высоты не применяются без полного перепостроения
и проверки траектории с DEM, ресурсом, скороподъёмностью и временными зонами.
Высота съёмки H1 неизменна. Ранее добавленные эвристики hold/altitude исключены
из выполняемого пути: они меняли высоту съёмки или время полёта без пересчёта
всех физических ограничений. Это не реализация всех ступеней лестницы ТЗ §15.

Перестановки / relocate / LNS остаются в `planner.py` (rungs 4/5/7 assignment).
`return_actions=True` возвращает список применённых rung’ов.

**Поиск минимальной безопасной задержки не реализован.** Одновременные полёты
разрешены, если выполняется условие сепарации. Геометрия задач H1 не меняется.

VRPTW проверяет маршрутизацию, но сам по себе не является тестом 4D-сепарации.

## 7. Воспроизведение проверки и границы уверенности

Из корня H2, с установленным проектом и pytest:

```bash
python -m pytest -q tests/test_deconfliction.py tests/test_mapf.py \\
  tests/test_checks.py tests/test_adversarial.py tests/test_planner.py
```

На 21.09.2026 эта команда в текущей среде дала **47 passed**. Это весь
выбранный набор, включая проверки ресурса и других инвариантов, а не 47
отдельных тестов исключительно на столкновение.

Проверка относится к кусочно-линейной модели. Она не доказывает точность
реальных траекторий, разворотов, навигационных ошибок и аэродинамики.
Без DEM нельзя заявлять проверку реального вертикального разделения.
Оболочки задач и цвет линий в viewer не участвуют в collision detector:
проверяются траектории с временем, а не пересечения рисунка задач.

Следующие полезные проверки пока не оформлены как отдельные регрессии:
разные вертикальные пороги пары; смешанные границы наземных/воздушных фаз;
устойчивость на почти касательных траекториях с большими координатами;
согласованность решения H2 и итоговой проверки H3 на одном плане и сцене.
Ни наличие 47 зелёных тестов, ни отсутствие конфликтов в H2 не заменяют
сквозную приёмку H3.
