# Контракт H3 dataset v1

Этот формат предназначен для парного датасета. Он не изменяет контракт
`gmp.h1_h2.v1` и не является заявлением о формате HTTP API сервиса.

## Вход

Векторы: GeoJSON FeatureCollection, WGS84 `[longitude, latitude]`.
Геометрические расчёты: `metadata.metric_crs = EPSG:32637`, метры.
`dem.tif`: одноканальный float32 GeoTIFF, та же метрическая проекция.
Ячейка задаёт постоянную высоту поверхности; между временными точками
маршрут линейный по метрическим X/Y и AMSL. AGL вычисляется относительно DSM.

| Файл | Содержание |
| --- | --- |
| survey_areas.geojson | Polygon/MultiPolygon, id, survey_type, payload_profile; отверстия не требуют съёмки |
| allowed_airspace.geojson | Разрешённая геометрия для всей траектории |
| no_fly_zones.geojson | Постоянные геометрические запреты |
| temporal_airspace.geojson | Запреты с active_from/to, min/max_alt_m; высоты AMSL, границы включены |
| landing_sites.geojson | Point, id, role=start/landing/both/reserve, candidate:boolean |
| obstacles.geojson | Геометрия, height_m над модельной поверхностью, horizontal/vertical_buffer_m |
| fleet.json | uavs: скорости, ресурс, резерв, интервалы разделения, совместимость, площадки, времена операций |
| payload_catalog.json | payload_profiles: геометрия камеры или line_spacing_m, GSD, перекрытия |
| mission.json | objectives, окна, ветер, service_time_min, validation_policy |
| metadata.json | Идентификатор, CRS, происхождение, модель высот, настройки генерации |

`gsd_cm` означает верхний допустимый GSD. `planning_gsd_cm` является более
строгой целью генерации на неровном DSM. `nominal_agl_m` соответствует этой
цели. Камеры являются явно заданными модельными конфигурациями, а не
утверждением о комплектации конкретного серийного БВС.

`line_spacing_m` у LiDAR/геофизики одновременно задаёт ширину непрерывной
полосы в принятой модели. Для камеры поперечный размер проекции равен
`AGL * image_width_px * pixel_pitch_um / 1000 / focal_length_mm`.
Линейное объединение прямоугольного поля зрения задаёт модельное покрытие.
Допускается не более 0,1% непокрытой площади **каждой** задачи.

Время: ISO8601 с часовым поясом; скорости м/с в маршруте, км/ч во флоте;
расстояния и высоты в метрах, длительности в секундах (ресурс входа в минутах).
AMSL в реальных сценах остаётся в вертикальном датуме EGM2008.
KML предназначен для обзора; геодезическая проверка опирается на JSON/GeoTIFF.

## Выход

Обязательные верхние поля:

```json
{
  "schema": "geoscan.h3.result.v1",
  "scene_id": "S00_smoke_rgb",
  "objective": "makespan",
  "status": "SAFE",
  "optimality": {"status": "unknown"},
  "metrics": {},
  "sorties": []
}
```

Это только схема полей, **не допустимый SAFE-ответ**: у него должны быть
непустые вылеты и проверяемые метрики. Каждый вылет содержит:
`id`, `uav_id`, `index`, `start_site`, `landing_site`, `t_start`, `t_end`,
`flight_time_s`, `distance_m`, `waypoints`.

Каждая точка содержит `lon`, `lat`, `agl_m`, `amsl_m`, `t`, `phase`, `job_id`,
`speed_ms`, `remaining_endurance_s`. Фаза и job_id описывают **входящий** отрезок
от предыдущей точки. У первой точки фаза takeoff. Вне survey `job_id = null`.
Время строго возрастает; одинаковые XY допустимы для вертикального движения.

`remaining_endurance_s = endurance_min * 60 * (1-reserve_fraction) - elapsed`.
Посадочный резерв уже вычтен; повторно вычитать его нельзя. Вылеты одного БВС
разделены обслуживанием. Резервная площадка не используется как штатная.
Взлёт и посадка образуют префикс/суффикс фаз в коридоре 100 м у площадок.

Метрики:

- `distance_m`: суммарная горизонтальная длина траекторий;
- `total_flight_s`: сумма длительностей всех вылетов, включая взлёт/посадку;
- `makespan_s`: последний конец минус начало пересечения рабочего и светового окон;
- `coverage_percent`: площадь покрытия; дополнительно проверяется каждая задача;
- `per_job`, `sortie_count`: подробности пересчёта.

Ожидание открытия воздушного пространства входит в makespan. Обслуживание
между вылетами входит в makespan, но не в total_flight.

`INFEASIBLE` содержит пустой `sorties` и `diagnosis.proof` с типом проверяемого
основания. У S06/S07 имя типа `unreachable_required_point` сохранено в v1,
но фактическая проверка сильнее: **вся** требуемая область недостижима.
Диагностическая point должна лежать в задаче, но сама по себе ничего не доказывает.

Неизвестные объекты, неполные обязательные поля, NaN/Infinity, неверные времена
и несогласованные метрики отклоняются. Статус SAFE имеет смысл только вместе
с ограничениями модели, перечисленными в README и отчёте проверки.
