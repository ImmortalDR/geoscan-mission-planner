# H3: входы и проверенные выходы Geoscan

Владелец: **Данила Бессмертный**. Пакет для проверки планировщика и демонстрации
proof of concept. Это данные и автономный проверяющий скрипт, не новый сервис.

## Что внутри

12 основных сценариев: 9 синтетических, 3 с реальным DSM.
**Сценарий** в каталоге UI — шаблон; **проект** — рабочая копия команды.

Групповые (для сложных алгосов H2): **S01** (4 БВС, ~100 км²), **S05** (2), **S11** (5).
Остальные с 1 БВС — oracle ограничений (ветер, NFZ, отказ, multi-sortie одного борта), не «дыры».
Ещё сильнее multi-UAV — H1→H2 bundles (`S01`×10): [`../docs/contract/H2_TEST_SCENES.md`](../docs/contract/H2_TEST_SCENES.md).

Для МГУ есть ответы для двух критериев. Для удалённой базы есть отдельная
пара с изменённым входом: ближняя площадка явно становится доступной.
Итого **14 проверяемых пар**: 11 допустимых планов и 3 обоснованных отказа.

| Сценарий | Вход | Проверяемый результат |
| --- | --- | --- |
| S00 | Простая RGB-задача | Полное покрытие, один БВС |
| S01 | МГУ с окрестностями, 100 км², 4 БВС | План для makespan и total_flight |

| S04 | Ограниченный ресурс одного БВС | Несколько вылетов с обслуживанием |

В каждой папке `scenarios/S*/`:

- `input/`: только исходная сцена, без маршрутов и ожидаемых ответов;
- `scenario.json`: назначение теста и ожидания, **не вход планировщика**;
- `expected/<objective>/result.json`: полный проверяемый ответ;
- `validation.json`: сохранённый отчёт, который можно пересчитать;
- `routes.geojson`, `routes.kml`, `schedule.json`: маршруты и расписание;
- `S06.../alternative/`: самостоятельная пара для изменённых условий.

## Проверить

Python 3.12. Зависимости проверки перечислены в `requirements.txt`.
После их установки интернет, H1/H2, сервер и ключи не нужны:

```bash
python run_dataset.py verify --integrity
python -m unittest discover -s tests -v
```

В текущем рабочем окружении вместо `python` можно использовать
`/root/h3/.venv/bin/python`.

Проверить свой ответ вместо эталона:

```bash
python h3check.py scenarios/S00_smoke_rgb/input /path/to/result.json
```

Код возврата 0 означает прохождение **заявленной модели проверки**, 1 означает
нарушение или неполные данные. Формат ответа описан в [SCHEMA.md](SCHEMA.md).
Другой корректный маршрут не обязан совпадать с эталонным. Его критерий
может быть лучше: у положительных эталонов `optimality.status = "unknown"`.
Отказ по тайм-ауту не принимается как доказательство невыполнимости.

## Что именно доказывается

Проверка независимо пересчитывает обязательную покрытую площадь, ограничения
по площадкам, времени, ресурсу, ветру, совместимости, высоте, геометрии
запретов и непрерывным сближениям. Пересчитываются метрики и согласованность
полей маршрута. Сохранённому статусу планировщика проверка не доверяет.

Достижимость посадки подтверждается оставшимся допустимым участком маршрута
при линейной модели ресурса. Это не анализ всех аварийных отказов.
Отказы S06/S07 опираются на консервативный нижний предел пути до всей задачи
и разрешённой посадки, S09 на отсутствие допущенных по ветру аппаратов.

**Границы:** непрерывная полоса съёмки вместо дискретных кадров; упрощённые
буферы самолётных поворотов вместо динамики; фиксированные путевые скорости;
ресурс пропорционален времени. Требуемые перекрытия задаются во входе и
используются при построении галсов, но независимая проверка не удостоверяет
фактическое продольное/боковое перекрытие кадров. Оптимальность не доказана.
`SAFE` нельзя использовать как разрешение или сертификат реального полёта.

## Реальная и синтетическая части

МГУ, Переделкино и Орехово — Домодедовская используют реальные вырезки
Copernicus GLO-30. Это **DSM**, включая влияние зданий и растительности,
а не очищенный рельеф земли. Высоты EGM2008; данные источника не являются
актуальным перечнем городской застройки или препятствий.

Все задания, площадки, ограничения, даты, ветер и операционные профили БВС
вымышлены для тестирования. Высоты и параметры съёмки выбраны для расчётных
сценариев, не для реального вылета над Москвой. Центры описывают окрестности,
а не официальные административные границы районов.

Происхождение и SHA-256 вырезок находятся в `input/metadata.json`;
источники, лицензия и обязательная атрибуция находятся в [sources/](sources/).
Общий [manifest.json](manifest.json) закрепляет файлы поставки.

## Воспроизвести генерацию

Готовые пары проверяются автономно. Для **новой генерации маршрутов** нужны
локальные canonical H1 и `h3`, их зависимости и интернет
при первом скачивании DSM:

```bash
python generate_inputs.py
python run_dataset.py build
python run_dataset.py manifest
```

Это не обещание побитовой повторяемости оптимизатора с временным бюджетом.
Сохранённые ответы закреплены контрольными суммами. Адаптер не изменяет код
H1/H2, но исправляет некоторые различия представления данных в памяти.
Подробности и обнаруженные проблемы: [GENERATION_NOTES.md](GENERATION_NOTES.md).
