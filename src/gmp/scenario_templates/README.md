# Дополнительные постоянные шаблоны

Снимки сохранённых пользователем сценариев от 25–27.09.2026 и дополнительные проверочные сцены.
Они дополняют исходные S00–S11 из внешнего датасета и доступны даже
в новом рабочем пространстве без прежней базы SQLite.

| ID | Источник или назначение |
|---|---|
| S12 | MSU_4bpla_4zones |
| S13 | MSU_4bpla_5Zones |
| S14 | MSU_geo401_and_201 |
| S15 | MSU_geo401 |
| S16 | Недостаток времени — решение не ожидается (MSU_geo401_RGB_and_Lidar) |
| S17 | МГУ: дозарядка по пути к другой базе |
| S18 | MSU_geo401_alotofZones (сохранён как MSU_geo401_RGB_alotofZones) |

Для S12–S16 и S18 `input/` содержит точные копии сохранённых входов, включая `dem.tif`.
Для S18 использовано запрошенное пользователем имя шаблона; исходное имя
указано в `promotion.source_name`. Числа в именах могут отличаться от текущего
числа областей. Описание карточки отражает фактические входные данные.
Исходный `metadata.scenario_id` сохранён как часть неизменённого входа;
ID шаблона в каталоге задаёт соседний `scenario.json`.
`promotion` в нём фиксирует источник и SHA-256 каждого входного файла.

Каталог включается в Python-пакет, Docker и установку сервиса через `src/gmp`.
В интерфейсе шаблоны защищены от перезаписи: изменения сохраняются как свой
сценарий. Расчёты и пользовательская база данных в шаблоны не включены.

## S19 — no wind

S19_payload_compatibility_no_wind добавлен 29.09.2026 как парный тест к
S11_payload_compatibility (wind). Отличаются только идентификатор/описание
и скорость ветра: S11 — 3 м/с, S19 — 0 м/с. Остальные входы, включая
геометрию, датчики, БПЛА, базы и DEM, совпадают. У S19 нет promotion:
это проверочный шаблон, созданный из S11 по запросу пользователя.

## S17 — дозарядка по пути к другой базе

Новый пример заменяет прежний S17 с 19 зонами. Четыре области сложной формы
на неизменённом реальном DEM МГУ из S18; Геоскан 401 снимает LiDAR,
Геоскан 201 — RGB. Оба начинают на Base_0 и заканчивают на Base_2,
а дозарядка разрешена только на Base_1. Коптер выполняет две задачи
за два вылета с семиминутным обслуживанием между ними; самолёт — за один.
В отличие от примеров с возвращением на исходную базу здесь показана
промежуточная зарядка при разных обязательных старте и финише.

Геометрия задач искусственная, рельеф реальный. Входы воспроизводятся
скриптом `scripts/generate_s17_refuel_relay.py`, без случайных величин.
Начало локальных координат не совпадает с границами ячеек DEM: это
исключает неоднозначный выбор соседнего пикселя при преобразовании координат
длинных галсов. Модель рельефа и допуски проверки не менялись.

S16 оставлен как отрицательный пример с явным предупреждением в названии.
Его входные файлы и исходные SHA-256 не изменены. Неполное покрытие и
статус незавершённого поиска не следует трактовать как доказанную
математическую невозможность: диагностика различает ресурс отдельного
вылета и отсутствие полного расписания в пределах поиска.
