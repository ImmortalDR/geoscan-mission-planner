# Geoscan H3: Safety & Ship

Рабочая область: независимая проверка планов, рекомендации, API, интерфейс,
экспорт и поставка. Владельцы H1/H2 сохраняют свои модули и контракт.
Этот документ описывает установку; фактические результаты испытаний и
известные ограничения находятся в `docs/H3_VERIFICATION.md`.

На момент подготовки коммита 21.09.2026 адрес https://45.87.246.124/
обслуживает просмотрщик H2, а `geoscan-h3.service` остановлена. H3 разворачивается
по инструкции ниже на отдельном адресе либо после согласованного переключения
служб. Не запускайте H3 поверх занятого порта 8090 или 443.
После развёртывания H3 пакет исходников и данных доступен через
`/api/v1/delivery` после входа. Секретный код в пакет не включён.

Исходники H1 и датасет передаются отдельно через параметры `--h1` и `--dataset`;
они не входят в этот H3-коммит. Ранние локальные изменения H1 не включены.

## Согласованный режим

- Русскоязычное общее пространство команды, вход по общему коду.
- Настоящий расчёт по умолчанию; эталонный просмотр отдельный и обозначенный.
- 12 демонстрационных сцен и независимая проверка каждой выдачи.
- ZIP/GeoJSON/KML/GeoTIFF, редактор карты и версионирование входов.
- Автоматическая загрузка открытого DSM с указанием источника; при ошибке
  источника требуется ручной файл, нулевая поверхность не подставляется молча.
- Изменяемые операционные параметры БВС помечаются пользовательскими.
- Проверенная рекомендация применяется только по выбору пользователя.
- Локальные снимки Sentinel-2 для МГУ, Переделкино и Орехово; переключение
  «Карта / Снимок». Дата 28.05.2025, 10 м/пиксель. Происхождение и подготовка:
  `docs/H3_MAP_IMAGERY.md`. Снимки являются подложкой, не входным DSM.
- KML/GeoJSON/JSON и PDF/DOCX; история и экспорты переживают перезапуск.
- Пользовательские проекты имеют срок хранения 30 дней; каталог исходных
  демонстрационных данных сохраняется независимо от рабочих копий.

## systemd: установка

Требуются Linux с systemd, Python 3.12, nginx, доступ к PyPI и исходники H1.
Код службы работает от отдельного пользователя `geoscan-h3`, а не root.
Существующий `gmp.service` на 8080 не перезапускается установщиком.

```bash
python3 deploy/install_h3.py \
  --h1 /root/H1_Scene_Coverage/h1_coverage \
  --dataset /root/TASK_danya/h3_dataset \
  --public-origin https://YOUR_SERVER_IP
```

При первом запуске установщик запросит код через скрытый ввод. Секреты
сохраняются в `/etc/geoscan-h3/environment` с правами 0600; не помещайте их
в git, клиентский JavaScript, скриншоты или пакет сдачи.

Установщик создаёт изолированную копию приложения в `/opt/geoscan-h3`,
состояние в `/var/lib/geoscan-h3`, включает `geoscan-h3.service`.
Приложение слушает только `127.0.0.1:8090`.

Для HTTPS установите сертификат и `deploy/nginx-h3.conf` отдельным nginx
server на 443. Сначала проверяйте `nginx -t`, затем выполняйте reload.
Порт 8090 не публикуйте в интернет. Сертификат и приватный ключ не входят
в поставку. Полезные команды:

```bash
systemctl status geoscan-h3
journalctl -u geoscan-h3 -n 100 --no-pager
curl --fail https://YOUR_SERVER_IP/health/ready
systemctl status geoscan-h3-cert-renew.timer
```

Установщик не перезагружает ОС. Автозапуск проверяется через
`systemctl is-enabled geoscan-h3.service`. Для обновления исходников повторите
установку в отсутствие активных заданий: каталог данных не заменяется.
Начатые вычисления при неожиданном перезапуске получают `ERROR`, а не `SAFE`.

## HTTPS без домена

Для публичного IP используются сертификаты Let’s Encrypt профиля shortlived
и Certbot 5.4+. Нужна автоматизация продления: срок сертификата около шести
дней. [Официальная инструкция](https://letsencrypt.org/2026/03/11/shorter-certs-certbot/).
HTTP-01 challenge обслуживается nginx из `/var/lib/geoscan-h3-acme`;
обычный сайт на 80 отключать не требуется. Таймер из `deploy/` проверяет
продление дважды в день и перезагружает nginx после успешного обновления.

## Переносимая поставка и Docker

Сборочный контекст включает только необходимые исходники, immutable dataset
и deployment-файлы, без секретов и рабочих пользовательских проектов:

```bash
python3 deploy/prepare_h3_bundle.py /tmp/geoscan-h3-delivery \
  --h1 /root/H1_Scene_Coverage/h1_coverage \
  --dataset /root/TASK_danya/h3_dataset
```

В полученном каталоге `compose.yaml` принимает через внешний env-файл:
`GMP_ACCESS_CODE`, `GMP_PUBLIC_ORIGIN`,
`TLS_CERT_FILE`, `TLS_KEY_FILE`. Сертификат должен соответствовать адресу.

```bash
docker compose --env-file /secure/path/h3.env up --build -d
docker compose ps
```

Не запускайте Docker-proxy на 443 одновременно с системным nginx на этом
порту. Docker-вариант является альтернативной установкой. После обновления
сертификата proxy должен перечитать его; при bind-mount отдельных PEM файлов
надёжный вариант `docker compose up -d --force-recreate proxy`.

## Проверка

Unit/API тесты, conformance и браузерное демо запускаются раздельно, чтобы
не выдавать один успешный health-check за полную приёмку. См. `DEMO_PATH.md`.
Из корня исходного проекта:

```bash
PYTHONPATH=src:../H1_Scene_Coverage/h1_coverage/src .venv/bin/python -m pytest tests/safety tests/report tests/api -q
PYTHONPATH=src .venv/bin/python scripts/verify_h3_references.py ../TASK_danya/h3_dataset --output artifacts/h3/references.json
.venv/bin/python scripts/smoke_h3_service.py https://YOUR_SERVER_IP --all-fixtures --output artifacts/h3/service-smoke.json
```

Последняя команда запросит код скрытым вводом и создаст обычные тестовые
проекты. Для переносимого пакета пути H1 и датасета: `../h1/src` и `../dataset`;
для API-тестов дополнительно задайте `GMP_DATASET_DIR=../dataset`.
Для браузерных проверок нужны Playwright/Chromium и Pillow, отдельно от
зависимостей службы; команда находится в `web/tests/h3_browser_smoke.py`.

H3 проверяет ограничения независимо от оптимизатора. `UNSAFE`, `INFEASIBLE`
и ошибки поиска не превращаются в частичный успех. У новых входов прежний
сертификат неприменим. Эталон не доказывает оптимальность маршрута.

Короткий общий код предназначен для контролируемого PoC. Он не обеспечивает
разделение пользователей и не подходит для конфиденциальных рабочих данных.
Для эксплуатации нужны более сильная аутентификация и согласованные политики
доступа, хранения и резервного копирования.
